**对前端和移动端最要紧的三条限制：**

1. **控制台只接受本机访问。** 它监听 `127.0.0.1`，并校验 `Host` 头必须是 `127.0.0.1:端口` 或 `localhost:端口`，带 `Origin` 时必须同源；没有 CORS 头。手机、局域网里另一台电脑、另一个端口上的前端开发服务器都**不能直接调用**。目前唯一的通路是 SSH 本地转发后在同一台电脑上访问。
2. **同一时刻只有一个操作者。** 控制权是 2 秒心跳租约，第二个页面使能会被拒绝。状态查询不受此限，多端可以同时只读。
3. **没有推送。** 没有 WebSocket 或 SSE，实时角度靠轮询 `GET /api/status`（现有页面 500 ms 一次，即 2 Hz）。

要给移动端和独立前端用，需要先补一层对外网关，见 §8。

## 2. 通用约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1，请求与响应都是 UTF-8 JSON（图片接口除外） |
| 关节编号 | 1–6：底座旋转、肩部俯仰、肘部俯仰、腕部俯仰、末端旋腕、夹爪开合。数组下标 0 对应 1 号 |
| 角度 | 度，整数。夹爪角度**越大越闭合** |
| 基座坐标系 | 原点在机械臂底座；X 向机械臂右侧，Y 向前（远离机械臂），Z 向上。`fk`、`keep_out` 用**米**；`*_cm` 字段用厘米 |
| 地图坐标系 | A4 地图近边中点为原点，X 向右，Y 远离机械臂，范围 X ±14.85 cm、Y 0–21 cm；字段名带 `map_cm` |
| 时间 | `t`、`observed_at`、`stamp` 等是 epoch 秒（浮点）。**板卡与开发机时钟不一致**，不要跨设备相减 |
| 配置透传字段 | `gripper`、`scene` 等对象里以下划线开头的键（`_note`、`_source`）是配置文件的注释，前端应忽略 |
| 错误体 | `{"error": "中文原因"}`，可直接显示给操作者 |

HTTP 状态码：

| 码 | 何时出现 |
|---|---|
| 200 | 成功 |
| 400 | GET 请求被拒绝（`Host`/`Origin` 不合规、读文件失败） |
| 404 | 路径不存在；`/api/frozen` 还没有冻结帧 |
| 409 | **所有 POST 的业务拒绝**：凭证错误、未使能、`revision` 过期、超限位、进禁入区、遇阻力、参数无效、未知路径 |
| 500 | 服务内部错误。此时服务端已自动撤销操作权，需检查后重新使能 |
| 503 | 没有画面或没有定位结果（`/api/frame`、`/api/phone`、`/api/annotated/*`） |

## 3. 控制会话流程

所有会让机械臂动的请求都必须走完这个流程。**指令不排队**：上一步没结束时发来的请求直接返回 409。

```text
GET  /api/bootstrap                    → 取 token、静态场景、首个 status
POST /api/enable   {owner, onsite}     → 拿到操作权，记下 status.revision
     每 ≤2 s  POST /api/heartbeat {owner}        （现有页面 600 ms 一次）
POST /api/jog      {owner, joint, delta, revision} → 返回新 status，更新 revision
     ……
POST /api/stop     {owner}             → 撤销操作权
```

| 概念 | 规则 |
|---|---|
| `token` | `GET /api/bootstrap` 返回；**每个 POST** 都要放在请求头 `X-Console-Token`。服务每次重启都会换，收到“页面凭证过期，请刷新”就重新 bootstrap |
| `owner` | 客户端自己生成的标识（1–80 字符，建议 UUID），**每个 POST 的请求体都必须带**，包括 `stop` |
| 使能 | `armed` 为 `true` 才能动。实机模式下 `enable` 还要求 `onsite: true`（操作者确认现场安全）和 2 秒内带采集时间的相机画面 |
| 心跳租约 | 使能后 2 秒内没有心跳即失效，**不能靠补发心跳恢复**，必须重新 `enable`。页面切后台、失焦时现有前端会主动 `stop` |
| `revision` | 状态版本号。动作类请求必须带上最近一次拿到的 `status.revision`，不一致返回“状态已变化”。使能、停止、切档、每次动作都会使它加 1 |
| 被拒绝之后 | 409 响应里没有新的 `revision`，而服务端的版本号可能已经变了：**收到 409 后先 `GET /api/status` 再发下一条** |
| 计划被拒 | 错误以“计划被拒绝，未发送任何指令”开头：机械臂没动，操作权保留 |
| 运动故障 | 遇阻力、回读失败、画面过期等：机械臂停在读回位置，操作权被撤销，`status.error` 有原因，重新 `enable` 时清空 |
| 超时建议 | 普通 POST 15 s；`/api/pose/execute`、`/api/home/execute` 120 s（请求在动作完成后才返回） |
| 请求体 | JSON 对象，1–32768 字节 |

`stop` 的语义是**不再下发后续指令**，已经发出的一段仍会走完（探索档每段约 0.5 s）。它不是硬件急停，`Arm_Action_Mode(0)` 是否等同急停未验证，界面文案不要写“急停”。

## 4. 控制台接口（`:8765`）

入口 `src/teleop/server.py`。离线模拟启动：`python3 src/teleop/server.py`（不接板卡，不发实机指令，接口行为相同，适合前端联调）。

### 4.1 查询（GET，不需要 token）

| 路径 | 返回 | 说明 |
|---|---|---|
| `/api/bootstrap` | `{token, scene, status}` | `scene` 是静态场景：`hand_eye`、`intrinsics`、`keep_out`、`map`（地图码布局与摆放），用于画 3D 视图 |
| `/api/status` | 状态对象，见 §5 | 轮询用 |
| `/api/frame` | `image/jpeg` | 腕部相机最新一帧；无画面 503 |
| `/api/phone` | `image/jpeg` | 第二路（手机）相机；未配置 503 |
| `/api/annotated/board`、`/api/annotated/phone` | `image/jpeg` | 画了检测框的定位结果图；仅实机模式有，否则 503 |
| `/api/frozen` | `image/jpeg` | 最近一次 `/api/freeze` 冻结的帧；没有则 404 |
| `/api/export` | `{schema_version, session, config_sha256, mode, samples, measurements, calibrations, calibration}` | 本次会话内存中的采样、标定、测量 |
| `/`、`/app.js`、`/scene.js`、`/style.css` | 现有调试页面 | 可作为调用示例参考 |

图片接口不带时间戳头，画面时间看 `status.camera`。现有页面只在画面面板展开时拉 `/api/frame`。

### 4.2 操作权（POST）

| 路径 | 请求体（另加 `owner`） | 返回 | 说明 |
|---|---|---|---|
| `/api/enable` | `onsite: bool` | status | 取得操作权。动作中、他人持有、回读超过 2 s 未刷新时拒绝 |
| `/api/heartbeat` | — | status | 续租 2 s；租约已失效时静默无效 |
| `/api/stop` | — | status | 撤销操作权。不校验 `owner` 是否持有者，任何持 token 的客户端都能停 |

### 4.3 运动（POST，需已使能，带 `revision`）

| 路径 | 请求体（另加 `owner`、`revision`） | 约束 | 返回 |
|---|---|---|---|
| `/api/jog` | `joint: 1–6`，`delta: ±1/2/5/10`（整数） | 限时档只允许 ±1/2；边界测试档只允许 ±1 | status |
| `/api/cartesian` | `axis: "x"/"y"/"z"/"pitch"`，`amount` | x/y/z：±0.5/1/2/3 cm；pitch：±1/2/5°；限时档 ≤1。夹爪尖沿基座轴平移或绕尖端改俯角，逆解失败或跳变过大则拒绝 | status |
| `/api/gripper` | `action: "wide"/"open"/"grip"` | 目标角来自配置：全开 11°、张开 30°、夹取 133° | status，`grip` 字段有判定 |
| `/api/pose/plan` | `target: [int × 5]`（J1–J5 目标角） | **不需要使能，不需要 `revision`**。只检查不发送；需探索档或标准档 | 计划对象，见下 |
| `/api/pose/execute` | `plan_id`，`revision`（用计划里的） | 计划 30 s 内有效，期间状态不能变 | status |
| `/api/home/plan` | — | 不需要使能。目标是观察位 `observe_v1` = `[90,105,5,5,保持,保持]`；当前在标准禁入区内时拒绝 | 计划对象 |
| `/api/home/execute` | `plan_id`，`revision`（用计划里的） | 同上，30 s 有效 | status |
| `/api/profile` | `name: "normal"/"explore"/"grasp"/"recover"/"boundary"`，`onsite: bool` | 限时档（后三个）需已使能且 `onsite: true`，60 s 后自动回默认档并撤销操作权。旧写法 `boundary: bool` 仍可用 | status |

计划对象（`pose/plan` 实测返回）：

```json
{"id": "94ab18bab03cf18e87b0811e", "created_at": 1791531546.38, "revision": 4,
 "start": [95,102,15,-2,95,133], "target": [90,100,10,10,95,133],
 "segments": 1, "largest_deg": 12, "seconds": 0.5, "margin_cm": 101.2}
```

`home/plan` 的 `segments` 是**分段姿态数组**（`[[90,102,8,8,95,133], …]`），`pose/plan` 的 `segments` 是**段数整数**，两者类型不同。`seconds` 是预计耗时，`margin_cm` 是路径上的最小禁入区余量（探索档不检查平台和桌面时会是很大的数）。

每次动作的执行方式：大步拆成小段（探索档 15°/段，标准档 5°/段），每段写入后回读核对，偏差超过 4° 即视为遇阻并停在读回位置。

限位档：

| 档 | 关节限位 | 禁入区 | 用途 |
|---|---|---|---|
| `explore`（控制台默认） | 课程限位，J2–J4 可到 −10° | 只显示余量，不拦截 | 有人盯着时探索 |
| `normal` | 软限位：J1 20–160，J2–J4、J6 5–175，J5 95–180 | 平台与桌面都拦截 | 与自动任务一致 |
| `grasp`（60 s） | 同 normal | 桌面余量降到 0.5 cm | 抓取最后几厘米 |
| `recover`（60 s） | 同 normal | 只允许余量不变差的动作 | 从禁入区退出 |
| `boundary`（60 s） | J3/J4 下限 2° | 桌面 1.5 cm，平台 3.5 cm | 边界测试，仅 1° 点动 |

当前生效的限位以 `status.limits` 为准，滑块范围应从它读取，不要写死。

### 4.4 记录、采样与标定（POST，不需要使能）

| 路径 | 请求体（另加 `owner`） | 返回 | 说明 |
|---|---|---|---|
| `/api/record` | `on: bool`，`label`（≤60 字），`note`（≤2000 字） | status | 开始/结束一段试验录制；录制中每一步保存画面和读数到 `episode_*` 目录 |
| `/api/sample` | `kind`（≤40 字），`label`，`note` | 采样记录 `{id, t, kind, label, note, state, image, camera, evidence, localization}` | 需机械臂静止且回读新鲜 |
| `/api/verify` | `kind: "grasped"/"boundary_clear"/"platform_contact"/"table_contact"/"released"`，`note` | 同采样记录 | 人工确认记录；两种 `*_contact` 会先执行 stop |

| `/api/calibrate` | `frame_id`，`plane`，`points: [[u, v, x_cm, y_cm] × 4–30]` | `{id, h, rms_cm, warning, …}` | 手工平面单应标定，只对该冻结帧有效 |

## 5. 状态对象

`GET /api/status` 以及大多数 POST 的返回。实测示例（模拟模式，节选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | `"simulation"` / `"hardware"` | 前端应明显区分显示 |
| `pose` | `[int × 6]` | **回读**角度。回读失败时元素可能为 `null` |
| `command` | `[int × 6]` 或 `null` | 最近一次下发的角度；与 `pose` 相差 1–3° 属正常（舵机死区、J2 下垂） |
| `target` | 同上 | 当前/最近一段的目标 |
| `observed_at` / `age_s` | 秒 | 回读时间及其年龄。`age_s > 2` 时应提示“回读过期”并禁用控制 |
| `armed` | `bool` | 是否有人持有操作权（不区分是谁） |
| `busy` | `bool` | 正在执行一步；此时任何动作请求都会被拒 |
| `error` | `str` | 最近一次故障原因，重新使能后清空 |
| `revision` | `int` | 见 §3 |
| `fk` | 对象，**米** | 各关节与夹爪尖在基座坐标系的位置；`tip_pitch_deg[0]` 是末端俯角（180 为垂直向下） |
| `clearance_cm` | `float` | 按标准禁入区模型算的最小余量，负数表示已进入禁入区。模型估计，不是测距 |
| `limits` | `{"1"…"6": [min, max]}` | 当前档的关节限位，键是字符串 |
| `profile` / `default_profile` / `profile_remaining_s` | | 当前限位档、默认档、限时档剩余秒数（非限时档为 0） |
| `grip` | 对象或 `null` | 最近一次夹爪动作。`result`：`holding` 夹住、`empty` 夹空、`not_closed` 没收拢（卡住或舵机没响应）；仅 `grip` 动作有 |
| `gripper` | 对象 | 夹爪标定配置透传 |
| `keep_out` | 对象，米 | 当前档禁入区参数，画 3D 用 |
| `camera` / `phone` | 对象 / `null` | `kind`：`none`/`live`/`replay`；`age_s` 画面年龄；`clock`：`capture` 表示时间来自相机采集时刻；`hardware_fresh` 为真才满足实机安全门 |
| `recording` | `{name, label, steps}` 或 `null` | 是否在录制 |
| `samples` | `int` | 本次会话采样条数 |
| `localization` | 对象或 `null` | 仅实机模式，见下 |

`localization`（按代码整理，约 1 s 更新一次，机械臂静止时才有效；下面是按字段结构写的示意，数值不是某次实测）：

```json

           "reprojection_px": 0.8, "servos": [90,105,5,5,92,30],
           "objects": [{"label": "red", "map_cm": [6.59, 12.53], "base_cm": [6.66, 19.28, 1.58],
                        "yaw_deg": -10.9, "bbox": [301, 188, 96, 90], "method": "top-face", "height_cm": 3,
                        "sticker": {"label": "Syringe", "category": "hazardous", "conf": 0.88, "bbox": [305,190,392,270]}}],
           "rejected": [{"label": "blue", "bbox": [0,10,40,60], "reason": "贴画面边缘"}],
           "official": [{"label": "Syringe", "category": "hazardous", "conf": 0.88, "bbox": [305,190,392,270]}]},
 "phone": {"error": "画面不可用或过期", "objects": [], "age_s": 1.2}}
```

- 每一路要么有 `error`（此时 `objects` 为空），要么有结果；结果超过 4 s 会被标为“定位结果过期”。
- `objects[].label` 是**颜色**（`red`/`green`/`blue`/`yellow`），不是垃圾类别。类别看 `sticker.category`（`kitchen`/`recyclable`/`hazardous`，官方模型没有 `other`），`sticker` 为 `null` 表示模型没认出；颜色到类别的兜底映射在 `config/sorting.json`。
- `objects[].bbox` 是 `[x, y, 宽, 高]`，`sticker.bbox` 和 `official[].bbox` 是 `[x0, y0, x1, y1]`，都是 640×480 画面像素。
- 位置精度是粗定位，`base_cm` 依赖地图摆放，不能当作抓取真值。

## 6. 板载相机服务（`:8080`）

入口 `src/adapters/board_camera_server.py`，监听 `0.0.0.0`，局域网内可直接访问（如 `http://192.168.137.100:8080/`），无鉴权、无 CORS 头。它是 `/dev/video0` 的唯一持有者，其他程序都应读它而不是自己开相机。按代码整理；2026-09-18 实测过 640×480 取帧。

| 路径 | 返回 | 说明 |
|---|---|---|
| `/snapshot.jpg` | `image/jpeg` | 最新一帧。响应头 `X-Frame-Time`（采集时刻，epoch 秒）、`X-Frame-Seq`（帧序号） |
| `/stream.mjpg` | `multipart/x-mixed-replace; boundary=frame` | MJPEG 流，`<img src>` 可直接显示；每帧带 `X-Frame-Time` |
| `/health` | `{device, frames, fps_since_open, latest_age_s, reopen_count, size}` | 健康检查 |
| `/` | HTML | 自带的看流页面 |

画面 640×480。跨域 `fetch` 读不到 `X-Frame-Time`（没有 CORS 头），用 `<img>` 显示不受影响。

## 7. 自动分拣与文件契约

### 7.1 自动任务（只有命令行）

这些脚本在开发机上运行，内部通过 §4 的 HTTP 接口驱动机械臂（封装在 `src/tools/console_step.py` 的 `Session` 类，可作为 Python 客户端参考）。**目前没有“开始分拣 / 停止分拣”的 HTTP 接口**，网页上的一键任务需要新增后端。

| 命令 | 作用 |
|---|---|
| `python3 src/pipeline/run.py [--dry-run] [--scan <目录>]` | 一轮完整分拣：扫描→注册地图→找方块→分类→抓取投放。`--dry-run` 只扫描和规划 |
| `python3 src/pipeline/loop.py --rounds N` | 分拣与打乱交替 N 轮，统计成功率；`--status` 只看不动 |
| `python3 src/tasks/sort_blocks.py [--dry-run] [--only red green]` | 较早的按颜色逐块分拣 |
| `python3 src/tasks/console_grasp.py where/observe/locate/hover/grasp/put/place/all` | 单步抓放动作 |
| `python3 src/tools/console_step.py status/jog/cart/grip/pose` | 单条受监督指令 |

自动任务运行时占用操作权，此时网页端只能看状态、不能控制；网页端调 `/api/stop` 会让任务在下一段停下。

### 7.2 运行日志 `log.jsonl`

> **2026-10-11 更新**：前端可依赖的事件与字段已定为[日志契约](18-日志契约.md)，并有 `/api/log*` 读取与推送接口（仿真后端已实现）。以它为准；本节保留作现状记录。

位置 `data/runs/console_grasp/log.jsonl`（`data/` 不入库；2026-10-11 已把一份副本放进 `docs/samples/log_real_arm.jsonl`）。每行一个 JSON 事件，都有 `t`（epoch 秒，写入方时钟）和 `event`。前端的运行日志页（B3）目前只能读这个文件，**没有 HTTP 接口**。

以下事件名和字段取自现有日志的实际内容：

| 事件 | 主要字段 | 含义 |
|---|---|---|
| `pipeline_start` | `run`，`cubes: [[x,y]…]`，`registration` | 一轮开始，列出找到的方块（地图 cm） |
| `scan_view` | `run`，`view`，`pose`，`markers`，`official` | 扫描的一个视角 |
| `pipeline_sorted` | `cube`，`category`，`bin`，`source`，`seconds` | 一块分拣成功 |
| `pipeline_missed` | `cube`，`category`，`reason`，`seconds` | 抓取或搬运失败 |
| `pipeline_skip` | `cube`，`category`（可为 `null`），`reason` | 跳过（证据不足、够不着等） |
| `planned` / `put_planned` | `tip_target_cm`，`pitch`，… | 抓取 / 投放规划 |
| `hovering` / `gripped` / `lifted` / `put` | `pose`，`tip_cm`，`grip`，`target` | 抓放各阶段 |
| `gripper_not_closed` / `gripper_awake` / `gripper_still_asleep` / `gripper_wake_refused` | `readback`，`attempt` | 夹爪舵机未响应及唤醒重试 |
| `tumbled` / `relocated` | `target_cm`，`category` | 打乱阶段 |
| `stopped` / `paused` / `sort_stopped` | `reason` | 任务中止 |
| `localized` / `look_pose` / `refine_view` / `category` / `sort_decision` / `sort_round` / `sorted` | | 定位、补拍、分类决策等过程事件 |

`category` 取值 `recyclable` / `kitchen` / `hazardous` / `other`，中文名在 `config/sorting.json` 的 `category_names`；`bin` 是目标地图码编号（40/41/43/44），实体容器到位后会变。`grip.readback`：约 129 面对面夹住、约 116 对角夹持、132 夹空、29 未动作。

需求规格里拟新增的 `mode_changed`、`unknown_object`、`bin_full`、`stall` 事件和 `image` 字段**尚未实现**；`interaction` 事件和语音/手势接口见[语音手势接口](25-语音手势接口.md)（仿真已实现）。

### 7.3 场景 `scene.json`

每轮扫描一份，位置 `data/runs/pipeline/<时间>/scene.json`，同目录有 `scene.png`（场景重建图）和 `view_NN.jpg`（各视角原图）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `run`，`t` | `str`，`float` | 运行目录、时间 |
| `registration.map_origin_base_cm` | `[float × 3]` | 地图原点在基座坐标系（z 不采用） |
| `registration.yaw_deg`，`.views`，`.spread_cm` | | 地图偏航、参与注册的视角数、各视角离散度 |
| `cubes[].map_cm` | `[float × 2]` | 块中心，地图坐标 cm |
| `cubes[].yaw_deg` | `float` | 块朝向，模 90° |
| `cubes[].colour` | `str` 或 `null` | 顶面颜色 |
| `cubes[].category` | `str` 或 `null` | 四类之一；`null` 表示证据不足 |
| `cubes[].source` | `str` | 类别依据的文字说明 |
| `cubes[].sticker` | `{label, category, conf, view}` 或 `null` | 官方模型在该块上的最佳检测及来源图 |
| `cubes[].detector` | `{xy, approx, votes, views}` | 多视角检测汇总；`approx` 为真表示位置仅近似 |

## 8. 与需求规格拟定接口的差距

需求规格 ④ 拟定了统一的“控制指令”POST 和 ≥2 Hz 的角度推送。对照现状：

| 拟定 | 现状 | 差距 |
|---|---|---|
| `cmd: set_joints`，`joints_deg: [int × 6]` | `/api/pose/plan` + `/api/pose/execute`（J1–J5）加 `/api/gripper`（J6） | 现有是“先预览再执行”两步，夹爪单独控制；可在网关里合成一步 |
| `cmd: move_to`，`target_cm: [x,y,z]` | 只有相对的 `/api/cartesian` 小步 | **没有绝对坐标移动的 HTTP 接口**。逆解 `dofbot_kinematics.inverse` 和路径检查已有，需封装 |
| `cmd: start` / `stop` | `stop` 有（`/api/stop`）；`start` 无 | 需新增任务启动与进度查询 |
| `cmd: set_mode`（manual/preset/auto） | 无 | 未实现 |
| `cmd: run_preset`（dance/stack/carry） | 无 | 未实现；预设动作本身也没写 |
| `cmd: unlock_bin` | 无 | 未实现 |
| `source` 字段 | 无；现有用 `owner` 区分客户端 | 需加入并写日志 |
| 角度推送 ≥2 Hz | 轮询 `/api/status` 可达 2 Hz；服务端每 0.3 s 回读一次 | 没有推送通道；运动中 `pose` 只在每段结束后更新 |
| 日志、场景经 HTTP 提供 | 只有文件 | 需新增读取/订阅接口 |
| 手机、局域网访问 | 仅 `127.0.0.1` | 需新增对外服务、鉴权和跨域策略 |
| 声光（W5）、定时（W4）、堵转事件（W6） | `Arm_Lib` 的 RGB/蜂鸣器 2026-09-18 实测可用，但没有封装成接口；堵转的回读核对已有，没有事件输出 | 未实现 |

建议的落地方式（待 A、B 确认，不是已定方案）：**不放开现有控制台的本机限制**，而是在它前面新增一个对外 HTTP 服务。它对局域网监听并做登录鉴权，作为唯一客户端持有控制台的 `token` 和操作权，对外提供需求规格里的 `cmd` 接口、任务启停、日志与场景读取和状态推送；所有运动仍经现有控制台下发，限位、禁入区、分段回读这些安全检查保持在一处。需要先定的问题：现场确认（`onsite`）在远程和手机端如何表达、多端同时在线时谁有控制权。

在这层服务就绪之前，前端可以这样并行开发：

- **首选：仿真后端**（2026-10-11 新增，见[仿真模块](16-仿真模块.md)）。`src/sim/sim_server.py` 提供本文 §4 的全部 `/api/*`（同一个 `Controller`，语义相同），并且有合成的相机画面、可抓放的物块、`status.localization`、仿板载相机的 `/snapshot.jpg` 与 `/stream.mjpg`；允许跨域，`--lan` 后手机和局域网可直接访问，不需要反向代理。它多出的 `/api/sim/*` 和 `status.sim` 只在仿真里有，实机上不存在，前端要按“可选”处理。

- **控制面板**：本机起离线模拟 `python3 src/teleop/server.py`，前端页面须由同一端口提供，或由开发服务器把 `/api` 反向代理到 8765 并把 `Host` 改写为 `127.0.0.1:8765`、去掉 `Origin`。
- **日志与统计页**：直接读现成的 `log.jsonl` 和 `scene.json` 回放（需求规格称已有 21 轮真实日志）。
- **移动端**：先做只读页面的布局与数据模型，数据源待对外服务确定。

## 9. 最小调用示例

与控制台同源的页面里（或经上述代理）：

```js
const owner = crypto.randomUUID();
const boot = await (await fetch('/api/bootstrap')).json();
const token = boot.token;
let state = boot.status;

async function post(path, data = {}) {
  const r = await fetch(path, {
    method: 'POST',
    headers: {'Content-Type': 'application/json', 'X-Console-Token': token},
    body: JSON.stringify({owner, ...data}),
  });
  const body = await r.json();
  if (!r.ok) {                       // 409：先刷新状态再决定下一步
    state = await (await fetch('/api/status')).json();
    throw new Error(body.error);
  }
  return body;
}

state = await post('/api/enable', {onsite: true});          // 实机须由现场操作者确认后才传 true
const beat = setInterval(() => post('/api/heartbeat').catch(() => {}), 600);

state = await post('/api/jog', {joint: 1, delta: 5, revision: state.revision});
state = await post('/api/gripper', {action: 'open', revision: state.revision});

const plan = await post('/api/pose/plan', {target: [90, 105, 5, 5, 95]});
state = await post('/api/pose/execute', {plan_id: plan.id, revision: plan.revision});

clearInterval(beat);
await post('/api/stop');
```
