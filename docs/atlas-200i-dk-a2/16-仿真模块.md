# 仿真模块（`src/sim/`）

状态日期 **2026-10-11**。独立模块：给新前端提供一个不接实机也能联调的后端，并用合成的腕部相机画面对四类检测模型做一致性检查。它不改 `src/teleop/`，旧控制台和旧页面只作参考。

**全部结论都是仿真结果**：Mac（Apple Silicon）、`uv` 临时环境（OpenCV 4.x、numpy、onnxruntime）、没有板卡、没有相机、没有发出任何实机指令。

## 1. 启动

```bash
uv run --with 'opencv-python<5' --with numpy --with onnxruntime src/sim/sim_server.py
```

| 参数 | 作用 |
|---|---|
| `--port 8770` | 端口 |
| `--lan` | 监听所有网卡，手机和局域网里的前端可直接访问（默认只监听 127.0.0.1） |
| `--map map_a4_v3` | 桌面地图：`config/map_*.json` 的文件名，或 `none` 不铺地图 |
| `--bins bins_acrylic_v1` | 按桶的设计文件在规划位置立起垃圾桶 |
| `--blocks 4 --seed 0` | 开始时随机放的物块数和随机种子 |
| `--speed 4` | 把每段动作后的等待缩短为 1/4（仿真舵机瞬时到位，默认按实机节奏等待） |
| `--model <best.onnx>` | 换检测模型，默认 `data/models/blocks4/v3/best.onnx` |

- 壳子页面 `http://127.0.0.1:8770/sim/`：三维机械臂与桌面、合成相机画面、检测对照、场景编辑，以及全部接口的列表和试调面板。
- 旧控制台页面仍在 `/`。
- 任何来源都可调用（`Access-Control-Allow-Origin: *`），不校验 `Host`。只因为这里没有实机才这样放开，**不要照搬到实机服务**。

## 2. 用了哪些模型和参数

仿真不自带几何，全部读取仓库里已经修正过的那一套：

| 内容 | 来源 | 实机依据 |
|---|---|---|
| 连杆与正逆解 | `src/spatial/dofbot_kinematics.py`（上游 URDF 尺寸，夹爪长 12 cm） | 触点标定水平残差 2.8 mm（[硬件实测](../05-板卡连接与硬件实测.md) 2026-09-25） |
| 桌面高度、地图摆放 | 所选地图 JSON 的 `placement.base_from_map`（v2/v3：z = −1.42 cm，地图原点在基座前 6.75 cm） | 同上，触点标定 |
| 相机位姿 | `config/calibration/hand_eye.json`，相机固定在腕部、不随 J5 转 | 独立姿态验证平均 1.4 mm |
| 相机内参与畸变 | `config/calibration/camera_intrinsics.json`（f = 977 px，k1 = −0.48） | 棋盘格标定 RMS 0.35 px |
| 限位、禁入区、使能与心跳、状态对象 | 直接复用 `src/teleop/core.py` 的 `Controller` | 与实机控制台同一段代码 |
| 物块贴面 | `data/reference/block_faces/` 的 20 张面 | 实拍 |
| 垃圾桶 | `config/bins_acrylic_v1.json` | **设计值，未切割、未测量** |

**2026-10-30 起**：按设计文件立起的桶改为透明壁 + 贴纸（码会被块和壁挡住），并新增桶摆放误差、舵机偏差、接触记录、挂沿判定和 `--bins` 分拣；用法和结果见 [24](24-垃圾桶建模与仿真联调.md)。下面“桶按不透明盒体画、桶板上的码不画”只对用户手动加的 `bin` 物体成立。

未建模：机械臂自身不出现在画面里（真实画面下缘可能看到夹爪）；抓取是规则判定（夹爪尖在物块中心 2 cm 内且够低就夹住，读回 129；夹空读回 132），没有推挤、翻倒和碰撞；舵机没有延迟、死区和下垂；桶按不透明盒体画，桶板上的码不画；各物块六个面的排布是假设的。

## 3. 接口

[接口文档](15-接口文档.md) §4 的 `/api/*` 在这里全部可用，语义相同（token、owner、revision、心跳租约都照旧）。差别与新增：

| 路径 | 说明 |
|---|---|
| `status.sim` | `{revision, blocks, holding}`；`revision` 变了就该重新取 `/api/sim/world` |
| `status.camera` | `kind: "live"`，`clock: "sim"`，`simulated: true`，`hardware_fresh` 恒为假 |
| `status.localization.board` | 旧控制台的地图定位跑在合成画面上，另加 `blocks4`（四类检测框）。官方三类模型需要 Ascend 运行时，这里没有。地图码位与 v2 不一致或不铺地图时不运行 |
| `GET /snapshot.jpg`、`/stream.mjpg`、`/health` | 仿板载相机服务（§6），带 `X-Frame-Time`、`X-Frame-Seq` |
| `GET /api/sim/world` | 桌面真值：`blocks[]`（`id`、`category`、`up`、`map_cm`、`base_cm`、`yaw_deg`、`held`、`inside`、`base_T_block`）、`props[]`（`kind`、`category`、`map_cm`、`holds`、`parts`、`base_T_prop`）、`map`、`holding` |
| `GET /api/sim/options` | 可选的地图、桶设计文件、类别、各类物块的面 |
| `GET /api/sim/detect[?conf=0.25]` | 检测模型在当前画面上的结果与真值逐块对照：`blocks[].result` 为 `correct` / `wrong_class` / `missed` / `ignored`，另有 `false_positives`、`summary` |
| `GET /api/sim/annotated` | 上一条的对照图 |
| `POST /api/sim/reset` | `{count, seed?}` 清空后随机放块 |
| `POST /api/sim/block` | `{category, map_cm, yaw_deg?, up?, id?}` 放一块或移动已有的块 |
| `POST /api/sim/remove` | `{id}` |
| `POST /api/sim/map` | `{name}` 换地图，`"none"` 不铺 |
| `POST /api/sim/prop` | `{kind: "bin", category?, map_cm, yaw_deg?, inner_cm?, height_cm?, wall_cm?, colour?}` 或 `{kind: "box", size_cm, …}` |
| `POST /api/sim/prop/remove` | `{id}` |
| `POST /api/sim/bins` | `{name}` 按设计文件立起全部桶 |

| `POST /api/sim/faults` | `{grip_miss}` 注入故障：合爪夹空的比例（0–1） |
| `POST /api/sim/sort`、`/api/sim/sort/stop`，`GET /api/sim/sort` | 让**真实分拣流水线**在仿真里跑若干轮、终止、查状态；要求 v2 码位的地图且桌上没有物体 |
| `GET /api/log`、`/api/log/stream`、`/api/log/records`、`/api/log/summary`、`/api/scene`、`/api/scene/image` | 事件日志与最近一次扫描，格式见[日志契约](18-日志契约.md) |

`/api/sim/*` 的 POST 同样要带 `X-Console-Token`，不要求使能；机械臂动作中会被拒绝（409）。

新地图只要在 `config/` 下放一个 `map_*.json`（含 `layout_m`、`side_m`、`placement`）即可被选用；可选键 `page_cm`（纸张尺寸，默认 A4 横向）和 `image`（相对仓库根目录的图片，铺满纸面）。三维物体目前由盒体拼成（桶 = 底板 + 四壁），不读 STL。

## 4. 检测模型的一致性检查

```bash
uv run --with 'opencv-python<5' --with numpy --with onnxruntime src/sim/evaluate.py -n 50
```

2026-10-11，Mac，`data/models/blocks4/v3/best.onnx`（onnxruntime CPU），地图 v2、无桶，50 个随机场景 × 6 个扫描姿态，每场景 4 块，阈值 0.25，IoU ≥ 0.5 算匹配，种子 0：

| 应检出 | 正确 | 类别错 | 漏检 | 误检 | 召回 | 精确率 |
|---|---|---|---|---|---|---|
| 518 | 499 | 9 | 10 | 20 | 96.3% | 94.5% |

类别错 9 次里 7 次是可回收物（5 次判成厨余）。结果在 `data/sim/eval_20261011_140714/`（不入库）。

**这不是实机精度。** 合成画面用的贴面正是生成 800 张合成训练帧的那 20 张照片，画面里也没有机械臂、真实光照和真实背景。它能说明的是：模型的前后处理、相机几何、真值框约定彼此一致；能发现的是成片的问题，例如同日在壳子页面里看到的——把桶画成不透明的类别色时，模型在桶壁上报出多个“厨余垃圾”误检（单次观察，未统计）。实体桶选色时值得在实机上核对。

渲染自检（`tests/test_sim.py`，22 项，需要 numpy 和 OpenCV，缺少时跳过）：合成画面里的地图码经 PnP 解出的相机位置与绘制所用位置相差小于 3 mm、重投影小于 1 px；物块画在前向投影模型给出的位置。

## 5. 真实流水线跑在仿真上

`src/sim/run_pipeline.py` 把 `src/pipeline/run.py` 原样指向仿真后端：同一套扫描、场景重建、规划、抓放和写日志的代码，只换了地址，产物写到 `data/sim/`，不与实机日志混在一起。2026-10-11 在 Mac 上：8 个视角扫描后地图注册为 (0.07, 6.76, −1.43) cm（标定值 (0.07, 6.75, −1.42)），重建出的 3 块中心与真值相差约 0.1 cm；连续 8 轮共 32 块，分拣 27、注入夹空 3、跳过 2（一块够不着、一块已在目标位）。

这说明流水线的几何、接口调用和日志在仿真里是自洽的，可以给前端提供与实机同形的事件流；**不说明实机成功率**——仿真没有舵机误差、夹爪不响应、物块被碰动这些实机上的主要失败来源。
