# 日志契约（`log.jsonl`）

状态日期 **2026-10-11**，契约版本 **1**。前端的实时状态、分拣记录、统计汇总、异常日志四个页面和记录导出，都只依赖这一份事件日志。本文规定前端可以依赖什么；规定以外的内容随代码变化，不作承诺。

- 契约的唯一来源是 [`src/tools/log_contract.py`](../../src/tools/log_contract.py) 里的事件表；下面的表格和 [`docs/contracts/log_event.schema.json`](../contracts/log_event.schema.json)（JSON Schema）都由它生成，测试保证三者一致。
- 写入方负责人 H1，读取方 F1、F2（见[分工与任务量](17-分工与任务量.md)）。改字段先改事件表、通知读取方，再改写入代码。

## 1. 现在能拿到什么

| 东西 | 位置 | 说明 |
|---|---|---|
| 实机日志样例 | [`docs/samples/log_real_arm.jsonl`](../samples/log_real_arm.jsonl) | 687 行，2026 年 9 月下旬至 10-09 实机运行的原始日志（只把本机绝对路径改成了相对路径）。含早期写法，逐块记录 18 条 |
| 仿真日志样例 | [`docs/samples/log_sim_8rounds.jsonl`](../samples/log_sim_8rounds.jsonl) | 277 行，8 轮：分拣 27、夹空 3、跳过 2。每轮都有完整的开始与结束事件，做页面先用这份 |
| 场景样例 | [`docs/samples/scene_sim.json`](../samples/scene_sim.json) | 一轮扫描的 `scene.json`，字段见[接口文档](15-接口文档.md) §7.3 |
| 活的数据源 | [仿真后端](16-仿真模块.md)的 `/api/log*` | 点一下就有新事件，见 §5 |

仿真日志由**真实的分拣流水线**（`src/pipeline/run.py`，一行未改）对着仿真后端跑出来，事件的名字、字段和先后顺序与实机相同；数值（耗时、成功率）是仿真的，不代表实机。2026-10-11 在 Mac 上验证：仿真里地图注册结果为 (0.07, 6.76, −1.43) cm，与触点标定值 (0.07, 6.75, −1.42) 一致；一轮 4 块全部落在目标码位 0.6 cm 以内。

## 2. 通用规则

- 文件每行一个 JSON 对象，UTF-8，只追加、不改写。每行必有 `t`（epoch 秒，浮点，写入方时钟）和 `event`（字符串）。
- **不认识的事件跳过，不认识的字段忽略。** 日志里约四成是规划与调试事件（`hovering`、`lifted`、`put_planned`、`refine_view` 等），不在契约内。
- 行号就是事件的序号 `seq`（从 1 开始）。文件里没有这个字段，由读取接口加上；“页面条数 = 日志行数”按它核对。
- 坐标 `cube` 是地图坐标 `[x, y]`，厘米；`pose` 是六个舵机角度（度，回读失败处为 `null`）；`bin` 是目标位编号的**字符串**（现在是地图码 `"40"` `"41"` `"43"` `"44"`，实体容器到位后会变成容器号）；`category` 是 `recyclable` / `kitchen` / `hazardous` / `other`，带 `?` 的可为 `null`（类别证据不足）。
- `run` 是一次扫描的目录名，只当不透明标识用（实机日志里有的是绝对路径，有的是相对路径）。
- `reason`、`source` 是给人看的文字，中英文都有，直接显示，不要解析。
- 板卡时钟比开发机快 8 小时：`t` 只和同一份日志里的其他 `t` 相减。

## 3. 事件

类型：`num` 数字、`int` 整数、`str` 字符串、`xy` 两个数、`pose` 六个数或 null、`list` 数组、`obj` 对象、`category` 四类之一；`?` 表示可为 null。“记录”一栏非空的事件各产生一条逐块记录（§4）。

### 已在用（stable）

| 事件 | 含义 | 必有字段 | 可选字段 | 记录 |
|---|---|---|---|---|
| `pipeline_start` | 一轮分拣开始；列出扫描找到的全部物块 | `run` str、`cubes` list、`registration` obj | — | — |
| `pipeline_sorted` | 一块已放到它的目标位 | `cube` xy、`category` category、`bin` str、`seconds` num | `source` str | sorted |
| `pipeline_missed` | 夹空或搬运途中滑脱 | `cube` xy、`category` category?、`reason` str、`seconds` num | — | missed |
| `pipeline_skip` | 没有去抓：类别证据不足、够不着、已在目标位等 | `cube` xy、`category` category?、`reason` str | — | skipped |
| `pipeline_approach_failed` | 接近途中遇阻，放弃这一块并退回观察位 | `cube` xy、`category` category?、`reason` str、`seconds` num | — | failed |
| `pipeline_put_failed` | 夹住了但放不到目标位，已就地或原位放下 | `cube` xy、`category` category?、`bin` str、`reason` str | `released` str | failed |
| `pipeline_cleared` | 把挡在别的目标位上的块先挪开（不算分拣完成） | `cube` xy、`category` category?、`bin` str、`seconds` num | `source` str | cleared |
| `pipeline_stuck` | 剩下的块互相挡着且挪不开，本轮到此为止 | `bin` str、`blocker` xy | — | — |
| `pipeline_end` | 一轮结束及计数 | `run` str、`sorted` int、`skipped` int、`missed` int、`cleared` int、`seconds` num | — | — |
| `scan_view` | 扫描到第几个视角 | `run` str、`view` int、`pose` pose | `markers` list?、`official` list | — |
| `gripped` | 合爪后的读回判定 | `pose` pose、`grip` obj | `tip_cm` list | — |
| `put` | 已在目标位松手 | `target` str、`released_at` pose | `target_map_cm` xy、`pose` pose | — |
| `gripper_not_closed` | 夹爪舵机没有响应合爪指令 | `attempt` int、`readback` num | — | — |
| `gripper_awake` | 小步唤醒后夹爪恢复响应 | `start` num、`readback` num | — | — |
| `gripper_still_asleep` | 唤醒后夹爪仍不响应 | `start` num、`readback` num | — | — |
| `gripper_wake_refused` | 唤醒动作被控制台拒绝 | `reason` str | — | — |
| `stopped` | 任务中止 | `reason` str | — | — |
| `table_z_disagrees` | 扫描得到的桌面高度与标定值相差过大，需重新标定 | `scan_cm` num、`calibrated_cm` num | `note` str | — |
| `interaction` | 手势或语音触发、且已被受理执行的指令（E1、E7）；被忽略或拒绝的不写；语音没有 `confidence` | `source` str、`command` str | `confidence` num、`detail` str | — |

`gripped.grip` 是 `{action, command, readback, at, holding, result}`，`result` 为 `holding`（夹住）/ `empty`（夹空）/ `not_closed`（没收拢）。

### 拟定（planned）

需求规格点了名、**还没有任何代码写入**的事件。字段是这次提出的方案，供页面先做起来；对应功能的负责人实现时如需改动，按本文开头的流程改。

| 事件 | 含义 | 必有字段 | 可选字段 | 记录 |
|---|---|---|---|---|
| `mode_changed` | 作业模式切换（W1） | `mode` str、`source` str | `previous` str | — |
| `unknown_object` | 发现不属于四类的物体，不抓取（E6） | `cube` xy、`image` str | `votes` obj | — |
| `bin_full` | 某个容器判定为已满，停止向它投放（E3） | `bin` str、`count` int | `category` category、`by` str | — |
| `stall` | 舵机堵转，已停止后续指令（W6） | `joint` int、`expected` num、`readback` num | `pose` pose | — |

`mode_changed.mode` 为 `manual` / `preset` / `auto`；各事件的 `source` 取 `web` / `mobile` / `voice` / `gesture` / `timer` / `button`；`unknown_object.image` 是现场图片的相对路径。

## 4. 逐块记录与统计

需求规格 B3 要求每条记录含六项。它们从事件里这样取：

| 六项 | 取自 |
|---|---|
| 时间 | `t` |
| 类别 | `category` |
| 来源坐标 | `cube` |
| 目标容器 | `bin`（跳过、夹空时没有） |
| 耗时 | `seconds`（跳过时没有） |
| 结果 | 由事件名决定：`pipeline_sorted`→`sorted`，`pipeline_missed`→`missed`，`pipeline_skip`→`skipped`，`pipeline_approach_failed` / `pipeline_put_failed`→`failed`，`pipeline_cleared`→`cleared` |

一轮是从 `pipeline_start` 到下一个 `pipeline_end` 之间的事件，记录的 `round` 是它所在的第几个 `pipeline_start`。`pipeline_end` 里的 `sorted` / `missed` / `skipped` 计数与该轮的记录条数一致（测试里核对过仿真样例）。实机样例是早期日志，只有一个 `pipeline_start`、没有 `pipeline_end`，大多数记录的 `round` 为 0。

`log_contract.records()` 和 `summary()` 是这套规则的参考实现；前端自己算或直接用接口返回的都可以。

```sh
python3 src/tools/log_contract.py check docs/samples/log_sim_8rounds.jsonl
```

```sh
python3 src/tools/log_contract.py records docs/samples/log_sim_8rounds.jsonl
```

## 5. 读取接口

仿真后端已实现；将来的对外服务（F1）对实机日志提供同样的四个路径，页面不用改。

| 路径 | 返回 |
|---|---|
| `GET /api/log?after=<seq>&limit=<n>` | `{contract_version, events: [{seq, t, event, …}], total, next}`。`after` 默认 0，`limit` 默认 500、最大 2000；下一次用 `next` 作 `after` |
| `GET /api/log/stream[?after=<seq>]` | Server-Sent Events：每行日志一条消息，`id` 是 `seq`，`data` 是带 `seq` 的事件 JSON。断线重连时浏览器自带 `Last-Event-ID`，从断点续传 |
| `GET /api/log/records` | `{contract_version, records: [{seq, t, round, run, category, cube, bin, seconds, result, reason, source}]}` |
| `GET /api/log/summary` | 各结果计数、各类别计数、完成轮数、全中轮数、单块耗时中位数、各轮耗时 |
| `GET /api/scene`、`/api/scene/image` | 最近一次扫描的 `scene.json` 与重建图；还没有扫描时 404 |

2026-10-11 在 Mac 上实测（仿真后端，本机回环）：三轮分拣产生 109 条事件，推送收到 109 条、序号连续；事件写入到推送到达的延迟中位 0.10 s、最大 0.21 s。这是本机数字，经局域网和浏览器渲染后的延迟要在前端验收时另测。

最小用法：

```js
const feed = new EventSource('/api/log/stream');      // 从头开始；只要新的就先取 /api/log 的 total 再带 ?after=
feed.onmessage = m => {
  const e = JSON.parse(m.data);
  if (e.event === 'pipeline_sorted') addRow(e.seq, e.t, e.category, e.cube, e.bin, e.seconds);
};
```

## 6. 让仿真产生日志

仿真后端要用默认地图（v2 码位）且桌上没有垃圾桶，因为流水线现在仍把物块放到地图码 40/41/43/44 上：

```sh
uv run --with 'opencv-python<5' --with numpy --with onnxruntime src/sim/sim_server.py --speed 4
```

然后三选一：
- 壳子页面 <http://127.0.0.1:8770/sim/> 的“分拣日志”面板点“开始分拣”，可设轮数和夹空比例。
- `POST /api/sim/sort {"rounds": 2}`；`GET /api/sim/sort` 看状态，`POST /api/sim/sort/stop` 终止；`POST /api/sim/faults {"grip_miss": 0.3}` 让三成的合爪夹空。
- 命令行 `src/sim/run_pipeline.py --rounds 3 --grip-miss 0.3`。

日志写到 `data/sim/log.jsonl`（不入库，与实机日志分开），每轮的扫描在 `data/sim/pipeline/<时间>/`。`--speed 4` 只缩短每段动作后的等待，一轮约 20 秒。

## 7. 已知的不足

- **没有任务启停的正式接口。** `/api/sim/sort` 只在仿真里有；需求规格里的 `cmd: start` 属于对外服务，尚未实现。
- **仿真里只能造出夹空和跳过。** `pipeline_approach_failed`、`pipeline_put_failed`、`pipeline_cleared`、`pipeline_stuck` 和夹爪唤醒类事件没有在仿真里触发过，样例里也没有；实机样例里有夹爪唤醒类事件。
- **近处的物块会让一轮直接出错退出。** 物块放在地图 y ≈ 6 cm 时，补拍视角求解失败，`refine` 抛出的异常没有被捕获，整轮中断且不写 `pipeline_end`。这是真实流水线的行为，仿真脚本只是避开了这个区域（物块只放在 y 9–17 cm）；实机上同样会发生，应由 H1 处理。前端要能容忍“有开始、没有结束”的一轮。
- **逐块事件里没有轮次编号**，轮次靠事件先后顺序推断；多个任务同时写一份日志时会错乱。现在同一时刻只有一个任务，暂不处理。
- 五个拟定事件只有字段方案，没有数据。
