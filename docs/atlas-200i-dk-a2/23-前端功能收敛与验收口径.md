## 0. 结论（先看 6 条）

1. **范围不变**：F1 = 电脑端 5 个职责面（概览、异常、控制、定时、未知物体，可表现为页签/侧栏/双页）+ 对外服务；F2 = 记录页、统计页、导出、手机端、状态条/来源、前端测试工具。需求规格 B3 的“4 个页面”由 F1（实时、异常）与 F2（记录、统计）**合起来覆盖**，不再要求 F1 独自做 4 页。
2. **三条硬口径**（本文 §3，必须同时进代码与验收）：①“条数一致”按**双视图**（事件条数 = 日志行数；记录条数 = 归并后的块记录数）；②“≤ 1 s”拆成**后端推送段 + 前端渲染段**分别测；③轮次按**一次 start = 一个任务 = 一轮**，历史/回放不计入。
3. **页面边界**：5 个职责面（概览、异常、控制、定时、未知物体）+ 共用页头与全局横幅；控制面板承担 W1/W2，定时页承担 W4，未知物体页承担 E6 的“展示”部分；预设动作（跳舞/叠积木/搬运）收进**调试模式**，未接入时禁用并给原因，**不删入口、不假装可用**。
4. **前端只做显示与门控**：能力裁剪看 `status.backend.capabilities`，不重算运动学/限位/禁区/统计/轮次/租约；唯一的执行侧与安全边界仍是控制台。
5. **PR #1 现状**：分层方向正确、5 个页签能渲染、接口 8/8 通过；但三个 P0（事件重复、角度双源、轮次翻倍）不达标，另有安全 B1、定时 B2、测试 B3 三个合入阻断项，**不建议按当前状态合入**。
6. **本轮之后**：F2 的四个缺项（记录页/统计页、导出、手机端、状态条+来源显示）与语音/手势页面接入按[分工](17-分工与任务量.md)排期推进；本文件先给出口径，避免两套实现。

## 3. 口径收敛（本文的核心）

### 3.1 “条数一致” = 双视图

需求原文在一句里并存两个口径（`10-需求规格:71`）：**“每条记录含 6 项”** 与 **“页面条数 = 日志行数”**；而 `log.jsonl` 是**每行一个事件**，事件行没有类别/容器/耗时。原样验收无法判定。

**本轮口径（写进页面页脚与验收记录）：**

| 视图 | 计数对象 | 验收断言 |
|---|---|---|
| 事件视图（实时/异常页） | 日志事件行 | 页头事件数 == `/api/log total`；SSE 按 `seq` 去重；用 `total`/`max(seq)`，不用 `events.length`（需处理 5 000 行上限） |
| 记录视图（记录页/本轮表） | 归并后的块记录（`pipeline_sorted/missed/skip/approach_failed/put_failed/cleared` 各一条） | 表格行数 == `/api/log/records` 长度 |
| 导出 | 记录视图 | 文件行数（不含表头）== 记录数 |

> 依据：[日志契约](18-日志契约.md) §4 的 `records` 六项与 `round` 规则；`seq` 是读取接口添加的行号。首屏回填 + SSE 重放必须按 `seq` 去重，不能靠“push 次数”。

### 3.2 “事件到展示 ≤ 1 s” 的测量点

板卡时钟比开发机快 8 小时（`10-需求规格:73`），跨设备没有共用时钟基准。**拆成两段分别测，验收记录必须写清测的是哪一段：**

| 段 | 定义 | 测量方法 | 验收阈值 |
|---|---|---|---|
| 后端推送段 | 日志落盘（`t`）→ 服务端 SSE 发出 | 同一台设备上比较 `t` 与 SSE 到达时刻 | 仿真实测中位 0.10 s、最大 0.21 s；仍按 ≤ 1 s 验收 |
| 前端渲染段 | SSE 到达 → DOM 更新 | 浏览器 `performance.now()` 差值 | p95 ≤ 1 s（20 次采样） |
| 端到端 | 写入方时钟 → 页面显示 | 仅在 NTP 对齐/同机时可用，记录校正量 | 不作为唯一判据 |

**页面延迟估计的基线**：取“最近一条回填事件的 `t` + 当时墙钟”，SSE 首条 live 事件后才开始计算；**回放/历史场景不得显示 0.00 s 冒充实时**，应标“回放”。（PR #1 的延迟恒 0 就是基线取错。）

### 3.3 轮次 = 一次 start 一轮（已确认）

> 一次 `start`（网页/定时/按钮/语音）= 一个任务 = 一轮；YOLO/流水线事件只作为本轮明细；历史与回放不计入任务轮次。

- `status.task` 字段：`supported / id / state / running / source / rounds_requested / rounds_done / current_round / started_at / finished_at / exit_code / error`。
- `current_round` = 任务开始后的 `pipeline_start` 数；`rounds_done` = 任务开始后的 `pipeline_end` 数；两者都只统计 `t >= started_at`。
- 明细：`GET /api/log/records?since=<task.started_at>`，`round` 从 1 起。
- **有开始没结束**：真实流水线在近端物块会异常中断且不写 `pipeline_end`（[日志契约](18-日志契约.md) §7），页面必须显示“第 x 轮未结束”，不能算完成。
- 无后端/无任务时：标“未启动任务（日志历史 N 轮，只读）”，**不得**把历史轮次显示成当前任务。

### 3.4 姿态单一来源

- 有后端：六轴显示、滑块初值、3D 骨架全部取 `status.arm.joints_deg` / `chain_cm`（控制台回读与正解）。
- 无后端：才允许用日志 pose 兜底，并在页头标“未接后端，姿态来自日志”。
- **禁止**同一页面混用顶层 `joints_deg`（日志 pose）与 `arm.joints_deg`（控制台 pose）。

### 3.5 页面集合边界

- **B3 的 4 页最小集合** = 实时状态、分拣记录、统计汇总、异常日志；其中前两页归 F1，后两页归 F2。
- W1/W2 的容器是**控制面板**页，E6 是**未知物体**页，W4 是**定时任务**页；这三页不算进“4 页”，但同样要验收。
- 手机端不新造页面集合：优先复用“统计/状态/启停”三个视图的响应式版本。

### 3.6 统计与导出口径（F2 用）

- 块成功率 = `sorted / (sorted + missed + skipped + failed)`；轮全中率 = `rounds_all_sorted / rounds_finished`（跳过、夹空都算未全中；`cleared` 是挪开挡路块，不计入分母）。
- 耗时：给“单块中位耗时”和“整轮时长”两列，不混用。
- 导出列（固定顺序）：`t, round, category, cube_x, cube_y, bin, seconds, result, reason, source`；空值留空，不写 `null` 字符串。
- Excel 用 `.xlsx`；CSV 用带 BOM 的 UTF-8；表头一行；文件名 `records_<yyyymmdd_HHMM>_<count>.xlsx|csv`。
- `bin` 只作不透明字符串展示，**不写死 40/41/43/44**，不按码位分派类别。

### 3.7 模式归属

- 模式状态以执行侧（控制台）为准；网关 `set_mode` 应转发并回读，**不另存一份**；无控制台时只在页面本地显示，不冒充已生效。
- “运动中切换先停在当前分段末尾”需先在[接口文档](15-接口文档.md)定义“分段”（建议：一条动作指令或一次分段执行中的一段，给出最大时长）。

### 3.8 能力标志（capabilities）语义

前端按能力裁剪，不按字符串 `"sim"` 写死：

```json
{"camera":true,"task":true,"task_rounds":true,"pose":true,"home":true,
 "profile":true,"gripper":true,"record":true,"sample":true,"verify":true,
 "freeze":true,"export":true,"sim_world":true,"localization":true,
 "calibrate":false,"measure":false,"onsite":false}
```

- `sim`：`task/task_rounds/sim_world=true`，`onsite=false`，`calibrate/measure=false`（接口可在，UI 不给入口）。
- `real`：`task/task_rounds=false`，`sim_world=false`，`localization/onsite=true`。
- 原名 `detect` 语义冲突（仿真合成检测 vs 实机定位），**拆成 `sim_world` 与 `localization`，删掉 `detect`**。
- `export` 指控制台的会话导出，**不等于 W3 的记录导出**；W3 另做导出接口/页面，不复用这个标志。
- 能力标志只决定 UI 显隐/禁用；接口不可用仍用 404/501/503 表达，前端要有空态。
- 无后端：`backend=null`、`arm.attached=false`、`task.supported=false`，页面进入只读历史模式。

### 3.9 鉴权与多端

- 对外服务默认本机可用；**`--lan` 必须强制 token**；token 通过 Cookie 下发，静态资源、API、EventSource 同源自动携带。
- 写操作只接受同源（`Origin == Host`）与 `application/json`；不得返回 `Access-Control-Allow-Origin: *`。
- “唯一客户端”改为**唯一持有写权限的客户端**：手机端可看统计/状态，可 start/stop，但不持有控制台 token。
- 手机端与电脑端“数据一致”定义：同一日志版本下统计数字相同，允许 ≤ 2 s 传播延迟。

### 3.10 数据与时钟边界

- 展示只依赖日志契约 v1（`src/tools/log_contract.py` 的 `EVENTS` 是唯一来源）；表外事件/字段忽略；`contract_version > 1` 时退回白名单只读。
- `t` 只在同一份日志内相减；跨设备时间不做差。
- `replay: true` 只用于回放标注，需在接口文档记录；不写入事件契约。
- 归档图片按名字取，`encodeURIComponent`（前端）+ `unquote`（服务端）配套，不 double-encode。

## 4. 期望（非功能与交付）

### 4.1 安全

- 未登录/无 token 默认拒绝写操作；局域网必须 token；跨源写请求拒绝。
- 所有日志字段进 DOM 前 `esc()`；页面不引入第三方脚本或 CDN。
- 前端不接触控制台 token；`onsite` 只是人工勾选，校验必须在后端。
- 文案不写“急停”；`stop` 只表示“不再下发后续分段”。

### 4.2 性能与资源

- 状态推送 ≥ 2 Hz；日志不得每 150 ms 全量重读（用 `after/next` 增量）；SSE 空闲发 keep-alive。
- 页面事件缓存要有明确上限（建议 5 000），超出时页头仍显示 `total` 并标“仅显示最近 N 条”。
- 长日志（> 5 000 行）下 A2 仍成立。

### 4.3 可测性（硬要求）

- Python：`python3 -m unittest discover -s tests` 全绿（PR #1 基线 38 例中 3 例红，全是跨平台断言）。
- 前端：至少一个可重复执行的 UI 冒烟（Playwright/Node 或等价），覆盖 A2/A3/A4/A9/A13/A14；失败要能出截图。
- 验收证据：日期、设备、浏览器、条件、数字、结论；不接受“已实现”作为结论。

### 4.4 文档与交付

- `src/web/README.md` 与实际页签/接口一致（PR #1 写 3 页签、实际 5 页签）。
- [接口文档](15-接口文档.md) §8 的差距表已注明“控制台自身差距、服务层已补齐”，不必回改；但 §8.1 的“换目标不改一行”要补实机限制（`enable` 需 `onsite`，当前写死 `false`，实机必拒）。
- 每个前端任务带测试与说明；接口字段变更先改事件表并通知读取方。

### 4.5 兼容与降级

- 无后端、无日志、无相机、无任务能力、接口 404/501/503 均有空态。
- `--token`/Cookie、`--lan`、反向代理三种部署方式都要验证静态资源与 SSE 可用。
- 回放模式不得截断活日志（`--replay` 与 `--log` 同用时先确认）。

### 4.6 界面语言与调试选项

- **页面可见文案不用课程描述词**：不出现“要求 / 验收 / 指标 / 课程 / 分工 / 人日 / 阶段 / 必做 / 排期 / W1–W6 / F1/F2 / H1/H2 / 需求规格 / 进阶”等；改用操作员语言（概览、手动操作、告警、任务计划、记录、扩展与调试）。编号与验收口径留在 `docs/` 与代码注释，不进入页面。
- **信息职责固定、版面自由**：固定 5 个核心面——概览、手动操作、告警（含异常物体）、任务计划、记录——加 1 个“扩展与调试”入口；不锁定页签数量、导航形态、版面、主题、密度与组件风格。任意页面都要能看到任务状态、设备连接状态并一键停止。
- **核心面常驻、扩展项默认隐藏**：核心为概览/观测、手动操作、告警（含异常物体）、任务计划（定时）、记录/导出、任务启停与停止；非抓取类附加能力——语音/手势、预设动作、标定/测量/采样/人工校验/冻结/录制/限位档、仿真世界/故障注入、原始事件与耗时——收进**扩展与调试**（设置开关或 `?debug=1`，状态持久化），按部署配置可提升为常驻。关闭时主界面不出现，开启后按能力显示，危险项二次确认。
- **完整操作面**：未连接→就绪→已使能→执行中→故障的状态机；主操作条（使能/解除、开始/停止任务、夹爪、回观察位、停止）；关节步进 + 滑块松手即下发（单飞队列）；直角方向键/摇杆 + 绝对坐标；场景目标选择；所有动作 pending→成功/失败，409 刷新状态后提示，不假装成功。
- **完整观测面**：顶栏（设备/连接/任务/延迟/事件数）、相机、三维姿态、场景地图、遥测（≤6 项）、当前动作、逐块记录、事件时间线、回读新鲜度；回放/空/断线/回读过期都有明确状态。
- **保留设计可能**：只固定信息职责与行为，不固定视觉方案；建议最小 token 集（间距 4/8/12/16/24、圆角 8/12、字阶 12/13/14/17/22、语义色），不强制框架或组件库；未来记录/统计/手机端与路径规划留扩展槽。
- 展开方案见 `.deploy/pr1/comment-ui-2026-10-23.md`（工作区分析稿，不入库）。
