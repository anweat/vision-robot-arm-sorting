# 垃圾桶建模、窄桌双桶方案与仿真联调

状态日期 **2026-10-30**。亚克力板已到手，要在桌面上做实机连调。本文记录：桌面有多窄、桶放哪里、仿真里怎么建模、管线怎么改、仿真跑出了什么，以及上实机之前和上实机时要核对什么。

**全部结论是仿真结果，没有碰实机。** 环境：Mac、`uv` 临时环境、`src/sim` 仿真后端；桶和地图都是设计值，没有打印、没有摆放、没有实测。

## 1. 先看结论

- **桌面只有 A4 长边宽（29.7 cm）**，原来的四桶布局放不下：1、4 号桶的底板整个在桌外，2、3 号桶一半悬空。先做**两类**：厨余垃圾（2 号桶）和有害垃圾（3 号桶）。
- 两个桶放在机械臂**两侧前方**（基座系 x = ±9.5 cm，y = 14.0 cm，耳板朝后）。这里正好是机械臂够不着取块的近区（离基座 < 17.5 cm），所以桶几乎不占取块区。代价：取块位只剩约 **4 个**（5 cm 间隔），空桌时是 10 个。
- 桶离机械臂太近，**相机在正常限位内看不到桶上的码**。双桶方案**不靠相机找桶**：桶按地图 v4 上印的落位线摆放，管线按设计位置处理。
- 地图 v4 去掉被桶压住的 12 枚码，**补了 11 枚**（近区 6、远排 5），共 19 枚。
- 投放槽位 ±1.2 cm，每桶装 4 块，装满后该类块被跳过。
- 仿真里（桶摆放误差 8 mm/4°、关节偏差 1.5°）：每桶 4 块全部落进对的桶，0 次蹭桶；槽位 ±1.8 cm 则有块挂在桶沿。

## 2. 桌面与桶位

桌面宽按 A4 长边 29.7 cm 算（|x| ≤ 14.85 cm），机械臂居中。深度**没量**，按 A4 短边 21 cm 保守算；更深只会更宽松。

| 桶（原四桶方案） | 底板 x 范围（基座系，cm） | 与桌面 |
|---|---|---|
| 1 | +13.9 … +28.8 | 整个在桌外 |
| 2 | +6.1 … +20.7 | 一半悬空 |
| 3 | −20.7 … −6.1 | 一半悬空 |
| 4 | −28.8 … −13.9 | 整个在桌外 |

`src/tools/layout_bins.py` 在桌面范围内搜双桶对称摆放：板子留在桌上（离平台前沿 ≥ 1 cm）、每个投放槽位机械臂都够得着、取块区（够得着的环带 17.5–26 cm，离板边 ≥ 2.5 cm）尽量大。取块位只数中间 |x| ≤ 9 cm。

选定：**中心 (±9.5, 14.0) cm，耳板朝后（+Y）**。两块底板之间隔 9.6 cm，离平台前沿 2.6 cm。取块位 4 个、面积约 56 cm²（无桶时 10 个、158 cm²）。耳板朝后是因为两侧各让出 4.7 cm 后，桶不会压到取块通道。

## 4. 仿真里怎么建模

在原有仿真（几何、相机、规则抓取）上加了：

- **透明桶**：底板和四面壁画成透明（叠一层淡色），上面的贴纸（耳板条白纸 + 两枚码、桶底白纸 + 一枚码）是不透明的、会被块和壁挡住。块落进桶里能隔着壁看到，桶底码被块盖住后检不出来。
- **桶摆放误差**：`/api/sim/bins` 接受 `jitter_mm`、`jitter_deg`、`offsets`、`only`。
- **舵机偏差**：`/api/sim/faults` 的 `servo_bias_deg`（关节 1–5）。机械臂真的偏了，回读和管线的正运动学不知道，这是对回差的一个替身。
- **接触记录**：夹爪手指（沿末端连杆的点）和被夹的块每走一步进入哪个桶，都记下来（不拦动作），`/api/sim/world` 的 `contacts` 里查。
- **落点判定**：块松手后若底面有一部分压在桶壁上，判“挂沿”，不算入桶。

没建模：手指的真实形状（只是线上的点）、块在手里的偏移（规则抓取把块当刚体）、透明亚克力的反光与折射、舵机延迟。

## 5. 管线改了什么

- **桶定位**（`bins.py`）：检出桶上的 5×5 码，按桶把同一块板上的码一起做平面 PnP，经正运动学 + 手眼换到基座系，多视角融合。仿真里无偏差时误差 ≤ 0.1 mm；关节偏差 1.5° 时约 6.5 mm、偏航约 1.5°。**精度上限是相机位姿的精度**（文档里一直说约 1 cm），够 80 mm 开口，不够毫米级。
- **桶口投放**：`console_grasp.plan_put/put` 加 `drop_tip_z`，指尖停在桶口上方松手，不再下放。指尖高度 = 台面 + 桶沿 4.2 + 夹取高度 1.2 + 余量 1.5 = **5.48 cm**（基座系）。投放后退回携带高度，而不是原地“上抬”（原做法目标与当前姿态相同，被控制台拒绝）。
- **路径禁入区**：桶是障碍，手指离桶壁不足 1 cm 的路径被拒（`PathBlocked`）。扫描里被挡的近视角直接跳过（记 `scan_view_skipped`），回观察位被挡就先抬到高位再绕。
- **补拍不绕桶**：已在桶里的块不补拍；补拍位姿找不到就跳过（原来整轮抛异常）。
- **容量**：每桶 4 个槽位，按够得着且软限位内的顺序用；已投数量写进 `data/runs/bins_state.json`（扫描数不到被叠住的块），装满记 `bin_full` 并跳过。**取空桶后运行** `python3 src/pipeline/run.py --bins bins_acrylic_v2_pair --empty-bins`。
- **半侧启动**：`--bin-side left|right|1,2`，只立所选的桶，只处理有桶的类别。双桶方案里 `right` = 2 号（厨余）、`left` = 3 号（有害）。
- **地图**：`ARM_MAP=map_a4_v4` 让管线、仿真读 v4（默认仍是 v2）。地图注册在没有视角看到 3 枚码时退到 2 枚。
- **收尾**：回观察位后定位核对失败只记 `observe_unchecked`，不抛。
- 日志：新增 `bins_located`、`bin_full` 转为在用，`pipeline_sorted` 加 `slot`、`drop_map_cm`（[日志契约](18-日志契约.md)）。

运行：

```bash
ARM_MAP=map_a4_v4 uv run --with 'opencv-python<5' --with numpy --with onnxruntime --with pillow src/sim/sim_server.py --map map_a4_v4 --speed 6
ARM_MAP=map_a4_v4 uv run --with 'opencv-python<5' --with numpy --with onnxruntime --with pillow src/sim/run_pipeline.py \
    --bins bins_acrylic_v2_pair --blocks 4 --rounds 3 --accumulate --bin-jitter-mm 8 --bin-jitter-deg 4 --servo-bias 1.5,-1,1,-1,0
```

## 6. 仿真结果（2026-10-30）

| 条件 | 结果 |
|---|---|
| 原四桶、规划位置、4 块 | 4 块分拣，3 入桶、1 挂沿（槽位 ±1.8） |
| 双桶、桶偏差 3 mm/2°、关节偏差 1°、槽位 ±1.2、4 轮累积 | 前两轮 8/8 入对桶；第 3、4 轮桶满，8 次 `bin_full`，4 块留在桌上，0 次蹭桶 |
| 双桶、桶偏差 8 mm/4°、关节偏差 1.5°、槽位 **±1.2**，2–3 轮 | 8/8 入对桶，0 次蹭桶（两次独立重复，其中一次末尾因“定位核对失败”中断，已改成容错） |
| 同上、槽位 **±1.8** | 第一轮 4 块里 2 块挂沿 |
| 同上、槽位 ±0.6 | 第二轮 8 块里 1 块没入桶 |
| 只立厨余桶（半侧）、3 轮 | 前几块入桶，满 4 块后被跳过，不再越界 |
| 未加禁入区时 | 扫描近视角、补拍路径的手指擦过桶沿（离桶壁 2 mm 内） |

槽位 ±1.2 cm 是这几个对比里最稳的，写入了 `config/sorting.json`。

**这不说明实机成功率**：仿真没有真实舵机误差、夹爪不响应、块在手里偏移、桶被碰动，这些是实机上的主要失败来源。

## 7. 实机联调前后要核对

`src/tasks/bin_checkout.py` 分三步，都不夹块：

```bash
python3 src/tasks/bin_checkout.py --design bins_acrylic_v2_pair plan                # 不动臂：每个槽位的落点、可达性
python3 src/tasks/bin_checkout.py --design bins_acrylic_v2_pair hover --bin 2 --slot 0   # 空夹爪走到桶口上方，停住给你看，再退回
```

`locate`（相机找桶）只对有观察位姿的设计可用；双桶默认没有，会说明原因。`hover` 会先要你输入 `y`。

**打印和摆放前**

1. 卡尺量板厚；不是 2.0 mm 就按 `docs/bins/README.md` §9 重生成。
2. 地图 v4 按 100% 打印，量 100 mm 校验尺。
3. 桌面**深度**量一下（本文按 21 cm 保守算）。
4. 桶按地图上的落位线摆，**固定住**；摆好后用直尺量中心的 x、y，记下来。
5. 地图 v4 的贴法若与 v2 不同（靠平台前沿的方式），**重做一次触点标定**；现在沿用的是 v2 的 5 点触点标定（水平残差 2.8 mm）。

**动机械臂之前**

6. `bin_checkout.py plan`：槽位全部“reachable”，J1 在软限位内。
7. 同一台电脑的另一个终端准备好停止。周围清空，有人站在机械臂旁边（项目约定）。

**第一次上手**

8. `hover --bin 2 --slot 0`：从上方看，空夹爪是否在桶口正上方；**张开的手指离桶壁多远**（仿真只看一条线，不看手指形状）；指尖高度读回与 5.48 cm 差多少（近全伸时机械臂会下沉 1–3°）。
9. 同样做 `--bin 3`。
10. 手动把一块放进夹爪，让机械臂只做一次“携带 → 桶口 → 松手”，看块落点是否在桶中央。
11. 再放 1 块、2 块自动分拣，之后才是一轮 4 块。

**随时停止的情况**

- 手指或块碰到桶壁、桶被碰动。
- 读回与指令差超过正常（遇到阻力）、`heartbeat failed/refused` 或 `internal error ... control locked` 出现。
- 块没落进桶中央、挂在桶沿。

**要记的数据**：桶的实测位置、每个块落点相对桶中心的偏差、指尖实际高度、哪个类别被识别错（可回收物易判成厨余）、`bins_state.json` 的计数是否和桶里实际块数一致。

## 8. 没解决、没验证

- **偶发控制被锁定**：仿真里长跑时偶尔出现“未使能、连接超时或正在运动”，控制器日志在客户端请求前就记了 `stop_future_commands`。起因没确认。我把心跳线程改成失败重试、服务端兜底改为打印异常，之后的约 7 次长跑里仍出现过 1 次（槽位 ±0.6 的第 3 轮），其余没有。所以**心跳线程不是已证实的原因，也不能说已修好**。实机上若出现，先看 `heartbeat failed` 与 `internal error` 两种输出。
- 相机找桶：双桶默认不用。若想用，先手动试 `…_relaxed.json` 里的位姿，J4 = −10 附近可能读回 −2…−3（2026-09-25 记录）。
- 手指形状、亚克力反光对贴纸检出的影响：仿真都没有。
- 近视角被跳过后，地图注册只剩高位视角；实机上要看注册是否仍稳（空桌仿真里 4 个高位视角各能看到 4–7 枚码）。
- 块的类别识别：仿真里可回收物易判成厨余，换成厨余+有害两类后影响较小，但没单独验证。
- 桌面深度未知；桶摆放的真实误差未知。
