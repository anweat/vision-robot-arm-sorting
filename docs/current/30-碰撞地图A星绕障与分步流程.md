## 1. 碰撞地图（外部输入）

[`app/src/planning/collision_map.py`](../../app/src/planning/collision_map.py) 定义的是一张 **2.5D 高度栅格**：
- 位于底座坐标系，单位米；
- 每格记录“格内东西的顶面离桌多高”，可附带物体标签；
- 文件格式为 JSON 或 npz，`format: dofbot-collision-map/1`，字段说明见模块头注释。

| 字段 | 含义 |
|---|---|
| `origin_m` / `cell_m` / `shape` | 栅格原点（第 [0][0] 格的角）、格宽（默认 2.5 mm）、行列数 |
| `height_m` | 离桌高度：0 表示空，null 表示未观测（按 `map.unknown_top_m` 处理，默认当空） |
| `labels` + `objects` | 每格的物体编号，以及物体清单（名称、类别、中心、尺寸、偏航、`sigma_xy_m`） |

- **高度相对桌面记录**：同一张图换一个桌面估计也能用。
- **平台和机械臂自身单独建模**：加载时会清掉平台面板上方的格子（`map.clear_platform`），因为深度图会把它们拍进去。
- **查询方式**：把每个碰撞点与“按余量半径做球膨胀后的地图”比较，算出竖直方向的余量。不同余量的膨胀结果会缓存，查询全部向量化。
- **栅格量化误差 ±半格**：物块按“格心落在物块外扩半格的范围内”填格，所以总体偏保守。
- **桶**：四面壁加底板合成一个物体，块可以从桶口放进去。

谁都可以写这张图，规划器只负责读。可以来自扫描定位（`flow.build_map`）、深度视图、仿真，也可以手写，`scene.Box` 列表也能直接光栅化成图。被抓的那块用它的标签排除出地图，再按精确盒子单独检查，因为合爪时允许贴到 0.5 mm。

## 2. 误差与微调：[`app/config/planning_tuning.json`](../../app/config/planning_tuning.json)

这个文件与 `motion_planning.json` 分开：后者只放模型事实，比如四连杆、开口档、俯仰候选、关节限位。这个文件里的每一项都可以按次覆盖，例如 `tuning.load(overrides={"errors": {...}})`、任务 JSON 里的 `tuning` 字段、或 CLI 的 `--tuning`；也可以用 `ARM_PLANNING_TUNING` 指向另一份文件。

| 组 | 内容 |
|---|---|
| `errors` | 目标 xy（5 mm）和偏航（5°）、障碍 xy（4 mm）和高度（3 mm）、桌面高（2 mm）、手臂 xy 和 z（各 3 mm） |
| `combine` | `rss`（默认，按独立误差求平方和根）或 `sum`（直接相加，最坏情况） |
| `clearances` | 误差之外的基础余量：邻物 4 mm、目标 0.5 mm、手臂连杆 5 mm、途中离桌 1 cm、指尖离桌 2/1 mm 等 |
| `trims` | 实机微调：桌面高修正、指垫高度（1.8 cm）、抓取和放置偏移（沿径向、向左、向上）、J5 修正、合爪指令、首选俯仰 |
| `search` | A* 参数（见第 3 节） |
| `map` | 未观测格怎么处理、是否清掉平台、地图外是否当空 |

各项误差进入哪些余量：

| 余量 | 由哪些误差组成 | 默认值 |
|---|---|---|
| 夹爪到邻物 | 邻物余量 ⊕ 障碍 xy ⊕ 手臂 xy | 9.0 mm |
| 张开的手指到目标 | 目标余量 ⊕ 目标 xy ⊕ 手臂 xy ⊕ 偏航误差带来的角点外扩 | 6.5 mm |
| 指尖离桌 | 指尖余量 ⊕ 桌面 ⊕ 手臂 z | 5.6 mm |

（⊕ 表示按 `combine` 的方式合成。）

合爪扫掠只在名义位姿上按 0.5 mm 检查，因为指垫本来就要贴上去。

**`trims` 只改指令，不改检查**：`Step.command` 等于模型关节角加上修正量，而余量检查始终按模型关节角做。

**误差直接影响能不能抓**。例如两侧邻块中心距 5.5 cm 时：
- 按默认误差规划会拒绝，原因里会点出邻块的名字；
- 把误差全部设为 0，就能用窄开口抓（`app/tests/test_motion_planning.py`）。

中心距 6 cm 时，按默认误差也能用 50 mm 的窄开口。

## 3. 路径：直线优先，否则用 A*（[`route.py`](../../app/src/planning/route.py)）

1. 先试关节空间直线，通过就直接用。
2. 不通时，在“FK 指尖位置”的格点上跑 A*：
   - **格点**：间距 1.5 cm，锚在起点的指尖上；z 取桌面以上 2–26 cm，xy 在起点和终点外扩 8 cm 的范围内。
   - **节点**：用 IK 求出让指尖落在该格点的位姿。俯仰和 J5 按“沿起点到终点直线走了多远”插值，够不到时退到 `pitches_deg` 里最近的一档。
   - **代价**：指尖行程 + 每度最大关节变化 0.4 mm + 近障碍惩罚（余量 2 cm 以内时最多加 1 cm）；启发项是到终点的直线距离，权重 1.2。
   - **检查方式**：节点用“隔 3 取 1”的稀疏点，余量额外加 3 mm；边在出队时才查（lazy），查不过就换次优的父节点。
3. A* 找到路径后先做捷径化：从每个点直接连到最远的可直达点。然后**每一段都用全部点重新检查**。
   - 若某段稀疏检查通过、全量检查不通过，就把这段拉黑，重跑 A*，最多 4 次。
   - 所以返回的路径从不依赖稀疏检查。
4. 起点或终点本身不净空时，会直接报“the start/goal pose itself is not clear: …”。

碰撞检查对象从“只查夹爪”扩展到整条手臂：
- link1–link4（上臂、前臂、带腕部相机的手腕）按课程网格体素化成点云，写进 `app/config/arm_links_geometry.json`（由 `dev/scripts/blender_extract_links.py` 从 blend 提取），检查它们离地图和桌面的距离（余量 1.2 cm）；
- 夹爪和被夹的块照旧检查。

旧测试里那堵 10 cm 高的墙，现在会被判为碰到腕部相机。

| 场景（离线，Mac） | 结果 |
|---|---|
| 2 cm 厚的墙挡在两个低位姿之间，墙高 6 / 10 / 14 cm | A* 可行，0.3 / 1.4 / 1.1 s，捷径化后 2–5 段 |
| 前臂扫过的位置有一根 14 cm 高的立柱 | 直线会碰到连杆，A* 绕开（约 2 s） |
| 立柱 18 cm | 无解（格点高度上限内没有通路） |

## 4. 抓取、放置拆开，再组合

| 模块 | 输出 |
|---|---|
| [`grasp.py`](../../app/src/planning/grasp.py) | `Target` → `Grasp` 候选（俯仰、J5、开口、指垫高度、悬停位、余量） |
| [`release.py`](../../app/src/planning/release.py) | `Destination` → `Release` 候选（放置位姿、上方位姿、开口、块的落点和水平度） |
| [`route.py`](../../app/src/planning/route.py) | `Route`（每段位姿和检查结果；方法是直线或 A*） |
| [`planner.py`](../../app/src/planning/planner.py) | `plan_pick` / `plan_place` / `plan_transit` / **`plan_pick_and_place`** → `MotionPlan` |

**`plan_pick_and_place` 按放置结果反过来选抓取**。抓取时块在指间的姿态就定了，这决定了放下时能不能保持水平。所以它会依次试抓取候选，直到某个候选也能放下。

放置的上方位姿依次试抬高 3 / 2 / 1.5 / 1 cm。之前固定抬高 3 cm，2026-11-06 实测场景的 b6 就放不下：它离底座 16 cm，用俯仰 160 抓，放到 (−5, 20) cm 时，俯仰 155/160 下“上方 3 cm”没有逆解，换成俯仰 150 块又会倾斜 10°。改为依次试之后，在俯仰 155 放下，倾斜 5.3°。

## 5. 分步流程：[`app/src/flow`](../../app/src/flow/)

每一步都是一个函数（`flow.stages`），也是一个 CLI 子命令（`app/src/flow/cli.py`）。会话目录 `data/flow/<时间戳>/` 存放各步之间传递的文件；每一步也可以直接指定输入文件，换成别的会话或外部地图。

| 步 | 输入 → 输出 | 动机械臂？ | 复用的旧代码 |
|---|---|---|---|
| `scan` | 扫描位姿 → `scan/`（views.json、图像） | 是（需 `--really`；实机还要现场确认） | `pipeline/field_scan.scan` |
| `locate` | 视图 → `located.json`（底座系下的块、桶，带 sigma） | 否 | `pipeline/run.build_scene`、`run.locate_bins` |
| `map` | located（+ 额外盒子）→ `collision_map.json` | 否 | — |
| `plan` | 地图 + 任务 → `plan.json`（抓取、放置、返回） | 否 | `app/src/planning` |
| `execute` | plan → 控制台指令，逐步回读 → `execution.jsonl` | 是（默认空跑；`--really` 才发送） | `tools/console_step.Session` |
| `verify` | 执行前后两份 located → `verify.json` | 否 | — |

- **`locate`**：用这次扫描自己的配准原点（x、y）把块放进底座系，因为地图会在两次会话之间被挪动（见第 6 节）。配准的偏航默认不用，与旧管线一致，可用 `--apply-yaw` 打开。sigma 取“误差配置”与“配准离散度”的平方和根。
- **`execute` 发指令前会检查三件事**：计划整体通过、每一步的检查都通过、手臂当前位置与计划起点相差不超过 3°。
  - 执行中每步回读，偏差超过 4° 就停；合爪后读到的不是 `holding` 也停。
  - 停在原地，不自动恢复，用控制台退出。
  - 控制台只有 wide/open/grip 三种夹爪动作，`narrow`/`tight` 用 J6 点动（10/5/2/1°）逼近。这条路径没在实机上验证过。
- **`verify`** 检查三件事：被抓的块离开了原位；放桌面时目标点有块，偏差 ≤ 1.5 cm；投桶时桌上少一块；其余的块都没动。
- **日志**：流程日志写在会话目录（`flow.jsonl`、`execution.jsonl`），**不进**前端的日志契约。只有 scan 仍会经 `console_grasp.log` 写 `scan_view` 事件，仿真时重定向到 `data/sim/`。

```bash
S=data/flow/demo
python app/src/flow/cli.py locate  --session $S --scan data/runs/pipeline/20261106_160502
python app/src/flow/cli.py map     --session $S
python app/src/flow/cli.py plan    --session $S --pick b6 --to-table -0.05 0.20
python app/src/flow/cli.py execute --session $S            # 空跑
python app/src/flow/cli.py verify  --session $S --after other_session/located.json
```

这几条命令要用带 numpy 的解释器跑；locate 还需要 opencv 和 onnxruntime，可以用 `uv run --with ...`。

**用实测数据离线跑（2026-11-06 那次扫描 `20261106_160502`）**：
- `locate` 找到 10 块；
- b6 → 桌面 (−5, 20) cm 规划出 10 步，空跑执行和 verify 都通过；verify 输入的执行后场景是人为构造的；
- 同一场景里多数块够不到：3 块离底座 > 28 cm，3 块在 25 cm 附近，其余的被 J5 单向范围限制。

## 6. 相机模型检验（实测图像，离线）

[`dev/tools/validate_camera.py`](../../dev/tools/validate_camera.py) 的做法是：
- 用录下的伺服回读，经 FK、手眼、地图摆放，把地图上 ArUco 标记的四个角投影到图像，**不做任何位姿求解**，和检测到的角点比；
- 同时把标记中心反投影到桌面，和版面位置比。

数据：2026-09-25 至 11-06 共 416 张带回读的视图，其中 345 张能看到标记。结果在 `data/reports/camera_validation_20261115.json`。

| 地图摆放 | 角点像素误差（中位 / p90） | 桌面误差（中位 / p90） |
|---|---|---|
| 每次扫描自己的配准 | 11.1 / 22.6 px | 0.30 / 0.62 cm |
| 触点标定摆放，09-25 至 09-27 | ~40 px | ~1.0–1.1 cm（地图整体偏了约 −0.87, +0.45 cm） |
| 触点标定摆放，10-09 / 11-06 | 11.5 / 12.4 px（中位） | 0.31 / 0.37 cm（中位） |
| 手眼标定用的 8 张（拟合数据本身） | 5.5 / 14.5 px | 0.13 / 0.36 cm |

由此得出：
1. **内参和畸变没问题**：每张图减去平移、滚转和缩放后，残差只有 1.1–1.6 px，而且不随离图像中心的距离增大。
2. **误差来自伺服位姿**：每张图有 ±1.5° 的滚转和约 10 px 的平移，与 `camera_model.py` 写的“约 1 cm 精度”一致。
3. **地图在会话之间被挪过**：9 月 25–27 日偏了约 1 cm，10 月又对上了。所以每次扫描都要做自己的配准，`flow.locate` 就是这么做的。
4. **桌面高度不稳定**：各次扫描拟合出的桌面，9 月约 −1.1 cm，11-06 是 −1.95 至 −2.2 cm；触点标定的值是 −1.42 cm。
5. 对照“中位 < 3 px、p90 < 8 px、高位视角 ≤ 0.5 cm”这条标准，**像素指标全部不达标**；按每次扫描自己配准，桌面误差中位达标、p90 不达标。规划里目标 xy 误差取 5 mm 就是依据这里的 p90。

**对仿真的影响**：仿真渲染和定位用的是同一套相机模型，没有位姿噪声，所以定位精度偏乐观：仿真里 ≤ 0.15 cm，实测 p90 是 0.6 cm。要让仿真的定位误差接近实测，应注入伺服偏差（仿真已有 `servo_bias_deg` 故障项），量级约 ±1.5° 滚转。

**还没做**：新近视角 `[62,106,5,0]` / `[118,106,5,0]` 还没有实拍；标记角点没有写进日志；`run.py` 的 refine 视图会覆盖 `view_06.jpg`（第 296 行与 `field_scan.py` 第 75 行命名冲突），这会让 11-06 的 5 次扫描里第一条 view_06 记录与图像对不上。

## 7. 仿真端到端（`dev/sim/flow_check.py`，2026-11-15，launch 配置 `arm-sim`）

在可达位置放 4 块，依次跑 scan → locate → map → plan → execute（走控制台接口）→ 再扫一遍 → locate → verify：

| 项 | 结果 |
|---|---|
| 定位 | 4/4 找到，位置误差 0.01–0.15 cm，偏航误差 ≤ 1° |
| 规划 | b4（kitchen）→ 桌面 (−4, 17) cm，11 步；另外 3 块各被拒 3 次（远块够不到；有偏航的块受 J5 单向范围限制） |
| 执行 | 11/11 步完成，回读偏差都在限内，接触 0 次 |
| 实际落点（仿真真值） | 离目标 0.12 cm；偏航从 5° 变成 18°（没要求朝向时保持搬运时的 J5） |
| verify（基于重扫） | 通过 |
| 用时 | 37 s |

如果用随机布局（`--layout random`），仿真生成的块多在离底座 13–15 cm。当时全部无解，原以为是 J3/J4 下限所致，**2026-11-15 查明是解算问题**（见 §10）。修正后，同一种子（7）端到端跑通。旧管线在实机上成功抓取的块都在 19–21 cm。同一次随机布局里，感知漏掉了 1 块近端的块，只靠检测器找到的块误差 1.3–1.6 cm。

## 8. 已知的结构性限制（不是本轮引入的）

- ~~J5 只能单向转（90–180°）~~、~~离底座 16 cm 以内基本够不到~~：这两条 2026-11-15 已更正，见 §10。前一条来自配置里的 J5 上限，后一条来自逆解缺陷和胖包络。
- **远处的朝向受 5 自由度限制**：24 cm 处俯仰最高约 145°。块的朝向偏离超过约 26° 时，开合轴会倾斜 15° 以上；这一条和 J5 范围无关。
- **陡俯仰抓起的块只能平放在近处**：块要平着放下，放下时须保持抓取时的俯仰和 J5（5 自由度下只剩绕竖直轴的转动），所以近底座用俯仰 165–170 抓起的块，放不到 17 cm 以外。
- **规划用的桌面和其他地方不一致**：规划用 −0.87 cm（加修正），仿真和地图用 −1.42 cm，所以仿真里抓取点要高约 5.5 mm。仿真的抓住判定（FK 指尖在 2 cm 内）没换成新模型。

## 10. 2026-11-15 更正：J5 范围、近处可达、误差分解与回正

### 10.1 J5：抓取可用 90–270°，挡相机只影响观察位姿

- 90–180° 这个上限只来自 09-26 操作员的一句“超过 180 夹爪舵机会转上来挡住腕部相机”（docs/05）。课程限位是 90–270°。
- 用相机模型做遮挡检查：把夹爪网格点按 J5 0–360° 投影到观察姿态 `[90,100,10,10]` 的画面里，张开的手指会出现在画面底部约四分之一（v ≥ 355 px），出现的角度是 J5 0–45° 和 150–210°；60–135° 和 255–330° 不挡。遮挡以 180° 为周期，因为两指是对称的。
- 下探抓取时不用相机，所以遮挡只限制观察姿态，不限制抓取姿态。
- 改动：
  - 规划用 J5 90–270°（`motion_planning.json` `joint_limits_deg.5`）。
