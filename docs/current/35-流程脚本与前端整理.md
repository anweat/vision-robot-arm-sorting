# 35 流程脚本与前端整理

更新：2026-11-27（§10 脚本清单）｜范围：YAML 流程脚本 v2（能力表、解析校验、各端共用的脚本库、运行）、观察脚本与连贯动作怎么接进流程、网页前端页面整理、需要板卡端补的接口。
流程的编辑与组装以本文为入口；扫描位姿、拍照、连贯动作各自的细节在 [42](42-观察脚本拍照与连贯动作.md)。

## 1. 一眼看懂

```text
app/src/flow/capabilities.py   能力表（唯一来源）：每项能力的参数、结果、会不会动臂、状态 ready/partial/unavailable
app/src/flow/script.py         解析 + 逐路径校验 + 脚本库（config/flows 内置只读，data/flows 各端保存）——纯标准库
app/src/flow/actions.py        新增的控制台动作：pose / gripper / speed / wait / wait_gesture / notify（及待接入的 led 等）
app/src/flow/orchestrator.py   编排器：按脚本执行；动臂前拒绝用到“不可用”能力的脚本；step 事件带 path
app/src/flow/moves.py          抓放怎么发：steps 每步一次移动，continuous 把能连的步连成控制台轨迹（42 §4）
app/src/pipeline/observe.py    观察脚本执行器 + 离线核对（app/config/observe/*.yaml，scan 的 observe 参数选哪份，42 §2）
app/src/adapters/capture.py    拍照一层：等停稳 → 取停稳后的帧 → 可选等板上定位结果（42 §3）
app/src/web/serve.py           网关：/api/scripts*（列表、读取、校验、保存、删除）、cmd=run_script
app/src/web/js/                网页：作业台首页 + 流程脚本 / 手动操作 / 告警 / 记录与日志 / 任务计划 / 设置
```

脚本只在服务端解析与校验，网页拿解析后的结构和带路径的问题来画，所以网页、之后的手机 App、板上编排器用的是同一套规则。

## 2. 能力表（板上现有能力）

`GET /api/scripts/capabilities` 返回整张表（也是网页「流程脚本 → 能力表」与「设置 → 板卡端待接入」的数据）。

| 分组 | 能力（`step:`） | 动臂 | 状态 | 说明 |
|---|---|---|---|---|
| 视觉 | `scan` 扫描识别 | ● | 可用 | 扫描位姿逐视角拍照 → 识别 → 定位块与桶 → 碰撞地图；`refine` 近看补拍；`min_views` 幻影门槛（§9.3）；`observe` 选观察脚本（`app/config/observe/`，默认 `field`，[42](42-观察脚本拍照与连贯动作.md) §2） |
| 视觉 | `relocate` 找回当前块、`verify` 核对 | | 可用 | 重扫后按位置找回；与本轮起始扫描比对 |
| 抓放 | `plan` 解算验证、`grasp` 抓取、`check` 抓后检查、`back_off` 张爪退回、`place` 放置 | ●（plan/check 不动） | 可用 | 原 S2–S6，要“当前块”（在 `for_each: blocks` 里）；`grasp`、`place` 的 `motion`：steps / continuous（不填按脚本顶层 `motion`，[42](42-观察脚本拍照与连贯动作.md) §4）；`plan` 的 `to: table` 不给坐标时自动找桌面空位，`to: stack` + `on: top` 叠到本轮的塔顶（§10.1） |
| 运动 | `home` 回观察位、`pose` 到命名位、`joints` 到关节角、`gripper` 夹爪、`speed` 速度 | ● | 可用 | `pose` 用 `arm_limits.json` 的 `named_poses`（新增平视位 `gesture_view`）；`joints` 六轴绝对角、`null` 不动；`gripper: grip` 按回读给 `holding` / `empty` |
| 交互 | `wait_gesture` 等手势 | | 可用 | 读网关的识别记录；识别端是 `bridge.py`（板上 hrnet.om），网页「手动操作」可开关，也可代发帧 |
| 交互 | `wait_voice` 等语音 | | **不可用** | 语音目前不可用（收音与识别进程未接） |
| 声光 | `led` 灯光、`buzzer` 蜂鸣 | | 可用 | 控制台 `/api/led`、`/api/beep`（PR #7；I2C 由控制台独占）；实机目视灯色正确，蜂鸣器未用耳朵确认 |
| 声光 | `say` 播报 | | **不可用** | 板上音频输出未核对 |
| 流程 | `wait` 等待、`notify` 提示 | | 可用 | `notify` 写一条 step 事件，各端弹出提示 |

状态的含义：**可用**＝控制台今天就能执行（实机与仿真同一接口）；**待接入**＝控制台一侧有接口，喂它的输入端没接，脚本照常运行，页面写明缺什么；**不可用**＝板卡端还没接口，脚本能写能存，但运行时在动臂前整份拒绝并写明缺什么（不跑到一半停在桌面中间）。

## 3. 脚本格式 v2

兼容原 `sort.yaml` 的写法，新增 `title`、`repeat`、`note` 和上面的新能力。

```yaml
name: gesture_scan            # 可选；文件名才是脚本的 id
title: 手势启动扫描            # 页面显示的名字
description: 等 OK 手势 → 扫描识别 → 回观察位；不抓取
speed: 20                     # 本流程期间的控制台速度 °/s（3–40）
motion: steps                 # grasp / place 怎么发：steps 每步停下核对；continuous 连成轨迹（2026-11-21，docs/current/42 §4，未上实机）
stop_after_alarms: 3          # 连续几块报警整轮停（默认 3）
steps:
  - step: notify
    with: {text: 比 OK 手势开始扫描}
  - step: wait_gesture
    with: {label: ok, timeout_s: 120}
    on_result:
      timeout: [{stop: 两分钟内没看到 OK 手势}]
  - step: scan
    with: {bins: bins_acrylic_v2_pair}
    on_result:
      empty: [{stop: 桌上没有找到物块}]
  - step: home
```

| 动作 | 写法 | 规则 |
|---|---|---|
| 执行一项能力 | `step: <能力>` + `with: {参数}` + `on_result: {结果: [动作], default: [动作]}` | 参数按能力表校验类型、枚举、范围；没写分支的不顺利结果：在 `retry` 里结束这次尝试，否则报警（块内跳过这一块、块外整轮停）。分支写成 `[]` 表示“这个结果是预期的” |
| 对每一块 | `for_each: blocks`、`order: reach\|scene`、`do: [...]` | 不能嵌套 |
| 重试 | `retry: {times, until, do, else}` | `do` 最多做 `times` 次，最后一步结果是 `until` 就停；都不行做 `else` |
| 重复 | `repeat: {times, do}` | 1–1000 遍；“停止”随时有效 |
| 报警 | `alarm: <类型>`、`then: skip_block\|stop\|continue`、`summary` | 写 `alarm` 事件，要人确认 |
| 记一笔 | `record: sorted\|missed\|skipped`、`reason` | 只在 `for_each` 里 |
| 下一块 / 停止 | `next_block: true` / `stop: <原因>` | |
| 备注 | 任何动作上的 `note:` | 只给人看 |

校验结果分两级：**错误**（不认识的键、参数类型/范围、`record` 放在块外……）不能保存也不能运行；**提示**（参数会被忽略、分支对应的结果这步不会给、用到待接入/不可用的能力）不挡保存。每条问题带路径，如 `steps[1].do[0].with.action`，网页点一下跳到那一行。

随应用发布的脚本（`app/config/flows/`）共 9 份，逐份说明见 §10.1：`sort`、`gesture_sort`、`retry`、`gesture_scan`、`gripper_check`、`dance`、`stack`、`carry`、`ready_signal`（等播报接口，现在运行会被拒绝）。

**手势与武装**：识别端武装时，手势还会执行 `interaction.json` 里映射的指令（`ok → start`）；只想让脚本“等手势”，就让识别端保持未武装——手势照样被记录，脚本照样看得到（仿真里实测如此，见 §6）。

## 4. 接口（网关，和板上同一份）

| 方法 路径 | 请求 | 返回 |
|---|---|---|
| `GET /api/scripts` | — | `{scripts: [{name, builtin, title, description, rev, ok, runnable, uses, moves, unavailable, partial, errors, warnings}], running, task}` |
| `GET /api/scripts/capabilities` | — | 能力表 + 控制动作说明 |
| `GET /api/scripts/<name>` | — | `{name, builtin, text, rev, mtime, check: {ok, errors[], warnings[], script, uses, moves, unavailable, partial, runnable}}` |
| `POST /api/scripts/check` | `{text}` | 同 `check`，不保存 |
| `POST /api/scripts/save` | `{name, text, rev?}` | 保存到 `data/flows/<name>.yaml`；内置名、有错误的脚本拒绝（400）；带 `rev` 且文件已被别的端改过 → 409 并附 `current` |
| `POST /api/scripts/delete` | `{name, rev?}` | 只能删保存的 |
| `POST /api/cmd` | `{cmd: "run_script", name}` | 起编排器跑这份脚本；有错误/用到不可用能力直接 409 并给原因；有未确认报警时语音/手势/定时来源被拒（同「开始」） |

**多端同步**：保存/删除写一条 `script_changed` 事件（[日志契约](18-日志契约.md)）。各端本来就订阅日志流，看到它就重拉列表；正在看的脚本没改动就自动刷新，有改动就提示冲突（载入对方版本 / 用我的覆盖）。运行进度靠 `step` 事件的 `path` 字段，各端都能把正在跑的那一行点亮。

「开始」按钮不变：仍默认跑已在实机验证的旧流水线（`--task pipeline`）；脚本走 `run_script`。

## 5. 网页前端

| 页 | 内容 |
|---|---|
| **作业台**（首页） | 现场画面：仿真时内嵌仿真工作台三维（`/sim/?embed=scene`），实机时画回读骨架（俯视 + 侧视，点位来自网关的正运动学）；腕部相机；并排/只看三维/只看相机可切。右侧：**操作**（开始、停止、选脚本运行、速度、夹爪、观察位/直立、模式）、**提示**（见下）、**设备状态**（控制台、操作权、运动、夹爪、末端、余量、六轴）。下方：**流程进度**（本轮计数、正在执行哪一步、正在跑的脚本结构树逐行点亮、最近步骤） |
| 流程脚本 | 脚本库（内置 + 已保存，标出动臂/不可运行/待接入/运行中）；结构视图可视化编辑（添加能力或控制动作、上移下移删除、表单改参数、加结果分支）；YAML 原文编辑；能力表；单步调试（原「任务」页的 S1–S7）；校验问题列表 |
| 手动操作 | 速度、夹爪、模式、关节滑块、坐标移动、小相机；扩展里的预设动作与语音/手势调试输入（手势按钮按 `interaction.json` 现行映射更正） |
| 告警 | 待确认的报警与告警（和作业台同一份）、异常事件明细与筛选、未知物体存档图 |
| 记录与日志 | 统计、逐块记录（本轮/全部）、原始事件流（可按事件名筛） |
| 任务计划 | 定时启动（未改） |
| 设置 | 网关与控制台连接、页面偏好（扩展与调试、报警提示音）、语音与手势规则（只读）、板卡端待接入清单 |

页头常驻：连接、控制台（仿真/实机）、任务状态、模式、**一键停止**；报警红条与定时待发横幅在任何页都显示；告警页签带未确认数量角标，标题加 ⚠。

**提示栏的三类**（作业台与告警页共用 `js/notices.js`）：

- **报警**（红）：流程脚本发的 `alarm`，要人点“知道了”；未确认时语音/手势/定时不能启动。
- **告警**（黄/红）：日志里的故障事件——抓空 `pipeline_missed`、接近遇阻、放置失败、物块互相挡住、夹爪没响应合爪/唤醒失败/唤醒被拒、桌面高度与标定不符、容器已满、未知物体、堵转。点“告警知道了”写 `alarm_ack kind="notices"`，各端同步清掉；新告警响一声（可在设置里关）。
- **状态**（不用确认，条件消失即消失）：和网关断开、未接控制台、回读过期、操作权在别处、控制台提示、进入禁入区、回放中、流程异常退出、定时待发。

### 9.3 仿真对幻影门槛的反证

同一轮里，`min_views: 3` 在**不近看**的收尾扫描把 3 块真块都当成了噪声（视角数 1–2），带近看的首次扫描也去掉了近端带 y = 7.8 cm 的一块真块（2 个视角）。

## 10. 脚本清单（2026-11-21）

现在有三类 YAML 脚本，都能不动臂先检查：

| 类 | 放哪 | 谁执行 | 改完怎么查 |
|---|---|---|---|
| 流程脚本：做哪些事、什么顺序、结果怎么分支 | `app/config/flows/`（内置，只读）、`data/flows/`（各端保存） | `app/src/flow/orchestrator.py` | 网页「流程脚本」校验，或 `POST /api/scripts/check` |
| 观察脚本：扫描时臂走到哪几个位姿、每处怎么拍 | `app/config/observe/` | `app/src/pipeline/observe.py` | `python3 app/src/pipeline/observe.py check <名>`：查限位、方台余量和路径（[42](42-观察脚本拍照与连贯动作.md) §2） |
| 仿真场景：桌面怎么摆、搬哪块到哪、怎么判对错 | `dev/sim/scenarios/` | `dev/sim/bench.py` | `bench.py run <名>` 接仿真控制台跑，`--set` / `--sweep` 调参（[16](16-仿真模块.md) §7） |

它们这样拼在一起：

```text
流程脚本  step: scan  with: {observe: field}  ──→ 观察脚本 field.yaml ──→ 每个视角：移动 → capture.shot（停稳、取帧、等定位）
          step: grasp / place  (motion: steps | continuous)  ──→ flow/moves.py 分组 ──→ 控制台 /api/pose（一步一次）或 /api/trajectory
仿真场景  不走流程脚本，直接调 flow/stages.py 的 scan / locate / build_map / plan / execute（同一套实现），按仿真真值判落点
```

所以要换扫描路线就改观察脚本，要换做事的顺序和分支就改流程脚本，两者互不影响。要比较参数（速度、容差、连贯与否），用仿真场景。

**叠积木与搬运（2026-11-21 补上）**：网关和网页的预设按钮 `stack`、`carry` 原来没有对应脚本，现在是 `config/flows/stack.yaml`、`carry.yaml`。为此 `plan` 加了两样（能力表先改）：

- `to: table` 不给 `table_m`：在纸面内找空位（`steps.TABLE_AREA_M`，A4 长边横放、四周留 1.5–2 cm），2 cm 一格；块的外接圆离别的物体外接圆 1.5 cm 以上、离原处至少 6 cm；由近到远试 6 个，用规划通过的第一个，都不通过给 `rejected`。
- `to: stack` + `on: top`：叠到本轮叠起来的塔顶；还没有塔时，当前块作塔底、不动，结果是新加的 `base`；塔到 `levels`（默认 3）块就给 `no_destination`。
- 放下后，场景按规划的落点更新（`steps._scene_after_place`：块移到放下的位置，叠在块上的记 `bottom_m`），下一块按更新后的场景规划。不重扫是因为普通扫描把每块都当成在桌面上，看不出叠层（[41](41-叠层感知与测高扫描.md) 的测高扫描还没做成步骤）。放进桶的块照旧处理。所以这两份脚本空爪时不重扫重试，重扫会丢掉更新过的落点。

仿真验证（2026-11-21，Mac，`sim_server.py --speed 4`，地图 `map_a4_v4`、桶 `bins_acrylic_v2_pair`，舵机故障 `stop_short_deg: 1.0`，种子 7，扫描定位，按仿真真值看结果）：

| 布局 | `stack` | `carry` |
|---|---|---|
| 中间 4 块（地图 cm：K (0, 13)、O (3.5, 17.5)、A (−3.5, 20)、B (4, 22.5)） | 3 层塔：K 作底，O、A 依次叠上（真值高 3.1、6.1 cm，和塔底水平偏 1–2 mm）；B 因塔满跳过；无接触；42 s | 3 块搬到空位（O、A、B 各移 7.5–8.4 cm）；K 试了 6 个空位都不通过（放下时夹爪碰 bin2 等），跳过；无接触；62 s |
| `scan_place` 的 4 块（H、R 紧挨桶） | 2 层：H、R 规划判定张爪会碰桶，跳过；无接触 | 没跑 |

跳过的块都是规划拒绝，不是脚本出错。实机没跑过：对齐、松爪后会不会带歪下面的块、放到空位后会不会碰到邻块，都要实机看。演示前先按 [05](05-板卡连接与硬件实测.md) 核对安全边界。

### 10.2 观察脚本（`app/config/observe/`）

| 脚本 | 内容 | 用在哪 | 核对 |
|---|---|---|---|
| `field` 整场扫描 | 原 `SCAN_POSES` 的 8 个位姿：高位 3 个、中位 1 个、侧位 1 个、近位 3 个；每处都等板上定位结果；路被挡住时跳过这个视角 | `scan` 的默认值；`field_scan.SCAN_POSES` 从这份读出来 | 8 个视角都通过，路径都是直达，离方台 +0.3～+3.4 cm（2026-11-21，离线） |
