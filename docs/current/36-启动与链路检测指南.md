# 36 启动与链路检测指南（板卡、本地前端、手机 App）

更新：2026-11-20。范围：怎么把三端起起来，怎么一条命令查清每一跳是否在线。这些脚本只读状态，不发运动指令。动实机前仍按[硬件安全边界](05-板卡连接与硬件实测.md)人工确认设备周围安全。

## 1. 链路与脚本

```text
Mac/电脑 ──Tailscale──▶ 跳板手机 App（:8090 网关转发，:2222 SSH 转发）──USB 共享 RNDIS──▶ 板卡
   │                       └ 转发到板卡广播里的网关端口（App 手填时用手填的）        ├ 相机 :8080
   │                                                                                  ├ 控制台 127.0.0.1:8765
   └ 本地：仿真控制台 :8770/8771 + 网关 :8090–8093（不接板卡时）                       ├ 网关 :8090（board_up.sh）
                                                                                      └ 广播 arm-beacon（UDP 37020）
```

| 脚本 | 在哪跑 | 作用 |
|---|---|---|
| `dev/tools/check_links.py` | Mac | **总检查**，按「本机 → Tailscale → 跳板 → 板卡 → 手机 adb」逐跳报告 ✓/!/✗，失败时给出修法；最后用板上各网关的口令经跳板请求一次，确认跳板实际转发到哪个网关 |
| `app/scripts/board_check.py` | 板上 `/root/arm-app` | 板卡自检：网卡（网线、手机 RNDIS）、广播、相机、控制台、**所有**网关进程（任何端口、各自口令）、板上仿真、负载。`--json` 给上面的总检查用 |
| `app/scripts/board_up.sh` | 板上 | 起相机、控制台、:8090 网关（已有）。2026-11-20 改：:8090 已有程序应答时不再重复起网关；结尾跑一次 `board_check.py` |
| `dev/sim/start_local.sh` | Mac/Linux | 本地仿真 + 网关（`start_windows.cmd` 的对应版本），`stop`、`status` |
| `dev/tools/phone.sh` | Mac | 手机的 adb 单步：`connect`、`rndis`、`app`、`sim`（adb reverse）、`install`、`status` |

输出里的符号：✓ 正常，! 警告（能用但要注意），✗ 失败（这一跳不通），· 仅说明。退出码只看 ✗。

## 2. 启动

### 2.1 板卡（实机）

```sh
# Mac：部署并重启三项服务（经跳板；网线时去掉两个变量）
BOARD_HOST=root@<手机 Tailscale IP> BOARD_PORT=2222 app/scripts/deploy.sh --restart
# 或只起不部署
ssh -p 2222 root@<手机 Tailscale IP> 'sh /root/arm-app/scripts/board_up.sh'
```

`board_up.sh` 的网关在 **:8090**，口令在板上 `data/gateway_token`。手动在别的端口另起网关时，跳板会跟着板卡广播（`board_beacon.py`）报的实际端口转发，App 的「板卡网关端口」留空即可；口令仍要填那个网关的（§4 第一条）。同一个实机控制台只接一个网关：两个网关会互相抢操作权，互相 409。

### 2.2 本地前端（仿真，不接板卡）

```sh
sh dev/sim/start_local.sh           # 仿真 :8771（A4 双桶）+ 网页 :8093，日志 data/web/local_*.log
sh dev/sim/start_local.sh stop
SIM_PORT=8770 WEB_PORT=8090 BINS= sh dev/sim/start_local.sh    # 手机 App 对仿真联调时的布局
```

Windows 双击 `dev/sim/start_windows.cmd`，端口与上面默认相同。

### 2.3 手机 App（跳板）

1. 手机插板卡的 **Type-A 口**，USB 功能要是 RNDIS：vivo 设置里的开关会自己弹回，用 `sh dev/tools/phone.sh rndis`。
2. 打开 Tailscale，再打开 App 的「连接」页，打开「跳板」。板卡地址留空，等广播。
3. vivo 要给 App 和 Tailscale 都开「允许后台高耗电」，否则退后台会被冻结，或掉出 tailnet（31 §2.1b）。
4. 手机插着板卡时，adb 用「无线调试」：`adb pair` 后 `sh dev/tools/phone.sh connect <IP:端口>`。`adb tcpip 5555` 会把 USB 功能复位、关掉共享，不要在插着板卡时用。

## 3. 检测

```sh
python3 dev/tools/check_links.py                         # 全部
python3 dev/tools/check_links.py --only local            # 只看本地仿真与网关
python3 dev/tools/check_links.py --board root@192.168.137.100   # 网线直连板卡，不经跳板
ssh -p 2222 root@<手机 IP> 'python3 /root/arm-app/scripts/board_check.py'   # 只看板卡
```

各端「在线且验证过」的判据：

| 端 | 判据（全部 ✓） |
|---|---|
| 本地前端 | 网关 `/api/health` 的 `console_ready=true`、`console_sim=true`；仿真 `/api/status` 200 |
| Tailscale | 本机 Running；手机节点 Online 且 `tailscale ping` 有回包（直连或 DERP） |
| 跳板 | 手机 :2222 能建连；手机 :8090 有 HTTP 应答（200/401）。只能建连、没有应答，说明跳板后面那个端口没有网关 |
| 板卡 | 经 SSH 自检：手机 RNDIS 网卡有 IPv4、相机最新帧 < 2 s、控制台回读 < 3 s 且无 error、至少一个网关 `console_ready=true` |
| 端到端 | 用板上某个网关的口令请求手机 :8090 返回 200，且 `console` 与该网关一致：说明跳板确实转发到了它 |
| 手机 adb | `sys.usb.state` 含 `rndis`；App 与 Tailscale 进程在且未被冻结；跳板服务在跑 |

板卡自检的时间按板卡时钟显示。板卡时钟与 Mac 差约 8 小时（时区未设），不要拿它和 Mac 的时间直接对比。

## 4. 常见故障

| 现象 | 原因 | 修法 |
|---|---|---|
| 手机 :8090 能建连但连接被重置；自检报「板卡 :8090 上没有网关」 | 板上网关被手动起在别的端口（2026-11-20 是 :8081，口令也不是 `data/gateway_token`），跳板仍转发到 8090 | 2026-11-20 起自动处理：`board_beacon.py` 每轮扫 `/proc` 里的 `web/serve.py`，广播实际在监听的 `--port`（多个时优先接实机控制台 :8765 且带 `--lan` 的；没有网关时报 `--gateway` 参数值，`gateway_from` 为 `proc`/`arg`）；App「板卡网关端口」**留空**时跳板跟随广播端口，连接页显示「网关端口：:8081（广播）」。仍连不上时看：板上 beacon 是不是新版（`board_beacon.py --once -v` 第一行打印检测到的端口），App 端口栏是不是手填了旧值（手填优先，清空后「保存跳板设置」并重开跳板）。口令要填该网关的。也可以在板上 :8090 起 `board_up.sh` 的网关（注意不要让两个网关接同一个控制台） |
| 手机 :8090、:2222 都连不上 | 跳板没开，或 App 被 vivo 冻结 | 打开 App、打开跳板；给 App 开后台高耗电；`phone.sh app` |
| 手机在 Tailscale 里离线 | 锁屏后 vivo 停了 Tailscale | 给 Tailscale 开后台高耗电，点亮屏幕重连 |
| 跳板 SSH 通但自检说没有手机 RNDIS 网卡 / 没有 IPv4 | USB 功能被复位（重插、`adb tcpip`） | `phone.sh rndis`；板上 `networkctl status usb1` |
| `tailscale ping` 走 DERP、延迟 150–400 ms | 没打通直连 | 能用；摇杆这类实时操作会更迟钝 |
| 本机 curl 访问 100.x 地址返回 502 | 终端里设了 `HTTP_PROXY` 等（Clash） | 脚本已忽略代理；手动 curl 时加 `--noproxy '*'` |
| 自检报负载约 20（4 核） | 板上同时跑着实机控制台、相机和板上仿真；kworker 在 uvcvideo 上 | 不影响检测；长时间偏高时先停掉板上仿真 |

## 5. 2026-11-20 实测

条件：Mac（Tailscale `anweats-macbook-air`）、手机 vivo V2339A（`v2339a`，App 跳板开着）、板卡 `davinci-mini` 经手机 USB 共享（`usb1` 10.83.74.213）。板上服务不是本次起的，是另一台机器（192.168.137.102）经网线手动起的：实机网关 :8081，仿真网关 :8091 加板上 `sim_server` :8770。只读检查，没有发运动指令。

| 项 | 结果 |
|---|---|
| 最初的问题 | 手机 :8090 建连后被重置。`board_check.py` 查出板卡 :8090 没有网关，网关在 :8081（口令与 `data/gateway_token` 不同） |
| App 改「板卡网关端口」后 | 端到端 ✓：本机 → 手机 :8090 → 板卡 :8081（实机）约 300 ms |
| Tailscale | 中转 DERP(tok)，148–413 ms，没有直连 |
| 板卡 | 相机 17–20 fps、最新帧 < 0.1 s；控制台 hardware、回读 0.1 s；负载约 21 |
| 本地 `start_local.sh` | 起仿真 :8771 + 网关 :8093 约 2 s（依赖已缓存），网页 200，`status`、`stop`、重复启动都正常 |
| 未验证 | `check_links.py` 的 adb 一节没有接真机测：手机 5555 关着，无线调试没配对。`board_up.sh` 的新判断没有在板上跑：板上服务正被别人使用，没有重启 |
| 跳板跟随广播端口（同日改） | Mac 上单测通过：`app/tests/test_board_beacon.py`（挑选规则、`/proc` 读不了时退回参数、`--once` 发出的包；真读 `/proc` 的一项只在 Linux 上跑，Mac 跳过）、App `GatewayPortTest`（6 项）与 `./gradlew assembleDebug`。**未上板、未装机**：板上 `arm-beacon` 仍是旧版（固定报 8090），要部署新 `scripts/` 并重启 `arm-beacon`；App 要重装。升级后 App 不再读旧的「板卡网关端口」设置（旧版每次开跳板都存成 8090，分不出是否手填），一律先走自动 |
