| `dev/` 的测试 | `dev/tests/` | — |

## 3. 环境与常用命令

两组单测都不需要硬件（Mac，Python 由 uv 管）：

```bash
uv run --with 'opencv-python<5' --with numpy --with onnxruntime --with pyyaml python -m unittest discover -s app/tests
```

```bash
uv run --with 'opencv-python<5' --with numpy --with onnxruntime --with pyyaml python -m unittest discover -s dev/tests
```

2026-11-22 的基线（提交 `e2c4570`）：`app/tests` 422 项、`dev/tests` 104 项，全部通过（2 项需板上环境而跳过）。提交前两组都要跑。

本地仿真 + 网页（不接板卡），Windows 用 `dev\sim\start_windows.cmd`：

```bash
sh dev/sim/start_local.sh
```

查链路（Mac → Tailscale → 跳板 → 板卡 → 手机 adb）：

```bash
python3 dev/tools/check_links.py
```

部署到板卡（经跳板，并重启服务）：

```bash
BOARD_HOST=root@<手机 Tailscale IP> BOARD_PORT=2222 app/scripts/deploy.sh --restart
```

Android 构建：在 `app/mobile/android/` 下执行 `./gradlew :app:assembleDebug :app:testDebugUnitTest`。`ANDROID_HOME` 指向本机完整的 Android SDK（2026-11-20 用的是 `~/Library/Android/sdk`；仓库根的 `.android-sdk/` 缺 `package.xml`，Gradle 认不出）。

## 4. 改代码的几条规矩

- **日志事件**：先改 `app/src/tools/log_contract.py` 的事件表，再重新生成 schema（`python3 app/src/tools/log_contract.py schema > app/contracts/log_event.schema.json`），前端按 [18](18-日志契约.md) 读。
- **流程能力**：先改 `app/src/flow/capabilities.py`，再在 `flow/steps.py` 或 `flow/actions.py` 实现同名步骤。板上还没有接口的标 `unavailable` 并写 `needs`。
- **流程脚本 YAML**：`off`、`on`、`yes`、`no` 这类值要加引号（`color: "off"`），否则会被解析成布尔值。2026-11-20 就因为这个，`dance`、`gesture_sort` 校验失败。
- **仿真**：`dev/sim/` 不导入 `Arm_Lib`，夹爪、整臂、底座用规划的同一套模型。仿真结果只说明几何与接口自洽，文档里不要写成实机结论。
- **新前端功能**只加在网关网页 `app/src/web/` 和 App 里。控制台自带的遥控页 `app/src/teleop/web/` 是维护模式，只修会妨碍调试的问题。
- **搬文件**：先写一张 `旧路径<TAB>新路径` 表，用 `python3 dev/tools/relocate.py 表.tsv` 先试跑，再加 `--apply`。它会 `git mv`，并改写链接和从仓库根算起的路径。代码里运行时拼出来的路径（`parents[n]`、`ROOT / "docs" / ...`）它不管，要自己查。

## 5. 上实机

1. 先在仿真里把要做的事整轮跑通（§3）。
2. 写进当周的实机清单（[37 §5](37-中期后任务清单.md)），注明会不会动机械臂。
3. 部署，然后在板上跑 `board_check.py`、在 Mac 上跑 `check_links.py`，都通过再继续。
4. **人工确认设备周围安全**。“停止”不是急停：`Arm_Action_Mode(0)` 未经验证。1–5 号单舵机写入不生效，用六舵机批量小步动作。
5. 同一个实机控制台只接一个网关。两个网关会互相抢操作权，互相 409。
6. 结果写进对应的现行文档：日期、设备、版本（提交 SHA）、条件、数字、证据路径。原始日志留在 `data/runs/`，汇总放 `records/`。

已知的坑：

- 板卡时钟比开发机快 8 小时，跨设备测延迟要用同一台设备的时钟。
- 板上和 Mac 的 OpenCV 版本不同，地图注册和朝向会差 6–9°。几何结论以板上为准。
- Windows 克隆后 `app/data` 软链接会变成文本文件，按根 README 用 `mklink /J` 修。
- vivo 手机要给 App 和 Tailscale 开「允许后台高耗电」。插着板卡时不要用 `adb tcpip 5555`。

## 6. 提交与 PR

- 从 `main` 开分支（PR #5 合入之前从 `ops-simplify-steps` 开），一个任务一个分支，PR 合回 `main`。提交说明用中文，写清做了什么、怎么验证的、哪些没验证。
- 基于旧布局（`src/`、`scripts/`、`tests/`）的分支先迁到新路径，对照表见 [34 §2、§10](34-仓库结构与应用版本.md)。
- PR 描述里分开写**实机验证**、**仿真 / 离线验证**、**未验证**三栏。
- 改了接口、日志事件或能力表的 PR，要同步改对应的现行文档（15、18、25、35），并在 PR 里点名受影响的另一端（网页 / App / 板卡）。
- 模型、贴面换版本时发新的 Release，不覆盖旧包，同时更新入库副本（`app/assets/models/`、`dev/sim/assets/`）。
