# 46 无需硬件的集成测试与统计

更新：2026-11-27。范围：整轮集成、异常恢复、读回统计（HT01/D1）、放下前修正开关（HT04/D4）、整轮验收统计。全部在电脑上的离线/仿真环境验证，不连接机械臂、板卡或真实相机。实机 T03/T04、R04/R07 的完成状态不因此改变。

## 1. 一条命令运行

在仓库根目录运行，需要 numpy、OpenCV、onnxruntime、PyYAML：

```powershell
uv run --with 'opencv-python<5' --with numpy --with onnxruntime --with pyyaml python -X utf8 dev/tools/offline_acceptance.py --out data/offline-acceptance/my-run
```

本机已有 `.venv` 时可以用 `.venv\Scripts\python.exe -X utf8` 代替前面的 `uv run ... python -X utf8`。输出目录必须是新目录；每次保留独立证据，不覆盖前次记录。Windows 跑两组全量测试前设置 `$env:PYTHONUTF8='1'`，已有部分模块读取中文 JSON 时依赖解释器默认编码。

入口运行 `test_place_correct.py`、`test_readback_stats.py`、`test_acceptance_stats.py` 和 `test_gateway_integration.py`。失败或跳过返回非零退出码；`report.json` 写设备、系统、Python/依赖版本、提交 SHA、工作区是否有修改、测试结果。`tests.out` 是详细输出，`gateway/` 留下流程、扫描、执行日志和仿真真值。

测试自动启动独立的本地仿真子进程和本地 HTTP 网关，使用临时端口、脚本库、会话和调参副本。没有接收实机地址的参数，也不复用已打开的控制台；结束后停止自己启动的进程。读取仿真 bootstrap 的 `mode` 后才布置场景。

## 2. 整轮集成测试

链路是：HTTP 保存 YAML → HTTP 启动 → 网关拉起真实编排器子进程 → 仿真相机扫描/定位 → 规划/抓取/放置 → 再扫描核对 → HTTP 查询日志、逐块记录与统计。

固定回归场景：`map_a4_v4`、两只 `bins_acrylic_v2_pair` 桶、一块厨余贴纸方块（鱼骨贴纸朝上，地图 `[0,21]` cm，朝向 5°）、随机种子 17、仿真速度倍率 100。扫描使用 `field`，第一次不近看，启用 `min_views: 3`。临时 tuning 副本仅按仿真桌面真值设置 `trims.table_z_m`，不修改仓库参数，不放宽碰撞/遇阻容差。

断言：编排器成功退出，逐块记录与统计一致，1 块 sorted、0 missed，复扫 verify=ok；仿真真值确认物块在桶里且不再被夹持，三个碰撞计数均为 0；真实生成的 `execution.jsonl` 能被读回统计工具分析。

范围限制：这是一个固定整轮场景，不是四类/十轮实机验收。探索时 `[0,13]` cm、未启用过滤的场景曾出现桶壁误检和规划拒绝；不能把此次通过推广到所有摆放。没有据此修改全局 `sort.yaml` 或模型。

## 3. 异常与恢复测试

| 条件 | 检查 |
|---|---|
| `grip_miss=1` | 发生重试，耗尽后记录 missed、产生 `grip_failed` 告警；HTTP 确认可清除告警，无 sorted |
| other 类没有匹配桶 | 记录 skipped，不生成执行日志 |
| 离线定位输入在不可达位置 | plan=rejected，记录 skipped，不发抓放动作 |
| 本地控制台端口断连 | 编排器非零退出，写 stopped，无 sorted |
| 两个并发启动请求 | 只有一个 HTTP 200，另一个 HTTP 409 |
| 等待期间停止 | 子进程已结束、后续步骤未运行，统计中保留未完成轮次 |

异常测试从仿真真值生成 `source` 定位输入，用于隔离执行/恢复规则；其中重扫读取的是同一份离线输入，不代表验证了故障后真实重新识别。整轮成功测试则实际执行相机扫描。网关为并发启动加锁，停止后等待执行子进程退出；会话名增加随机后缀，避免同秒启动覆盖记录。

## 4. 读回统计（HT01/D1）

```powershell
python -X utf8 dev/tools/readback_stats.py data/offline-acceptance/my-run/gateway --json data/offline-acceptance/my-run/readback.json
```

可传多个 `execution.jsonl` 或会话目录，递归寻找并按绝对路径去重。按关节、指令增减方向、passing 分组；方向相对前一条指令，新执行段用 start 的读回作起点。运动步骤统计 J1–J5，夹爪步骤统计 J6。

同时给出“读回减指令”的有符号分布和绝对误差分布：数量、中位数、p90、最大值。p90 使用 nearest-rank。默认分析最终读回；`--readback first` 优先用补发前的 `first_readback`。连贯模式通过 `stop: false` 识别 passing；中间没有读回时计入 `missing_readbacks`，不补零。坏 JSON 行列入 warnings 并使 CLI 返回非零。

## 5. 放下前修正开关（HT04/D4）

```yaml
- step: place
  with: {correct: false}
```

能力表 `place.correct` 是布尔值，默认 `true`。经 `steps.place`、`_execute` 传给 `stages.execute(correct=...)`。仅关闭放下前的持块位置修正，不关闭逐步补发、路径检查或控制台安全检查。网页/App 的能力目录自动取得新参数。

逐步与连贯两种模式均检查：开启时 lower 行包含 correction 记录，关闭时没有；字符串 `"false"` 不作为布尔值接受。现有 YAML 不写这个参数时沿用开启行为。

## 6. 整轮验收统计

```powershell
python -X utf8 dev/tools/acceptance_stats.py data/offline-acceptance/my-run/gateway/test_full_round_scan_to_truth_records_and_reports/log.jsonl --expected-blocks 1 --json data/offline-acceptance/my-run/acceptance.json
```

新流程按 `step: flow` 的 started/终态分轮，旧流水线按 `pipeline_start/end` 分轮；旧流水线中断块的解释复用 `run_stats.py`。不以时间间隔猜轮次。可读多个独立日志；目录输入只递归读取 `flow.jsonl`，不要同时输入同一轮的网关日志和会话日志。

结果包含 sorted/missed/skipped/failed/unfinished/cleared 数量、整轮状态、重试、告警、原因、步骤/整轮/逐块耗时；有首次失败和最终记录时给出本机日志可观测的处理耗时。缺少终态的轮次保留 unfinished；verify=mismatch 不算整轮全部成功。`--expected-blocks` 把没有记录到的物块计入分母并列为 unaccounted，避免漏块抬高成功率。

软件报告成功与落点核验分开：`reported_success_rate` 是日志里的 sorted；默认落点未知。可用 `--placements measurements.json` 导入独立观测：

```json
[{"round":1,"block":"b1","verified":true,"evidence":"simulation truth / 量尺照片路径","target_m":[0.10,0.20],"measured_m":[0.103,0.204]}]
```

round 是本次报告的 1 起轮号，block 是报告里的块名。重复、找不到的观测及缺少证据的观测会告警。提供目标/实测坐标时计算毫米偏差。未全部观测时 `verified_success_rate=null`，只给已经证实的下界 `verified_fraction_lower_bound`；不把日志 sorted 当落点证据。
