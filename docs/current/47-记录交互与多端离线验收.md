# 47 记录、交互与多端离线验收

更新：2026-11-27。范围：无需硬件任务 6–11；网页记录与导出、Android 模拟器、语音/手势事件输入、仿真场景、统一检查和落点记录模板。延续 [46](46-无需硬件的集成测试与统计.md)。结果只说明软件/接口/仿真自洽，不代替实机 T06–T09、T11 的最终验收。

## 6. 网页记录与导出

记录页提供本轮/全部、类别、结果筛选，每页 100 条；导出全部筛选结果而非当前一页。CSV 带 UTF-8 BOM，正确处理引号/逗号/换行和公式前缀；Excel 导出为可由 Excel 打开的 SpreadsheetML XML。读取失败保留上次数据并显示重试；记录数与统计不一致时重试，仍不一致则保持旧快照。

## 7. App 流程脚本

任务页读取同一网关 `/api/scripts*`：列出脚本、显示步骤、运行可用脚本；按事件 `path` 显示 started/done/failed/result，并显示与确认告警。切换所选脚本或执行会话后不沿用旧高亮；不可用能力维持拒绝。Android 模拟器使用 `adb -s <emulator-serial> reverse` 连接本地测试网关，不使用真机。

## 8. 语音与手势事件链

向本地网关输入识别结果，验证指令词映射、停止优先、武装、置信阈值、连续帧、保持只触发一次、冷却、告警阻止自动启动和确认恢复。实际运动请求只发本次启动的本地仿真控制台。`wait_voice`、`say` 仍为 unavailable；这些测试不能证明收音、识别率或播报可用。

## 9. 仿真回归

`offline_edges.yaml` 固定种子 17：不可达目标必须规划拒绝且不执行；正常目标在 `stop_short_deg=1.5` 故障下执行入桶，逐步和连贯各跑一次。`vertical.yaml` 以 `stop_short_deg=0` 检查叠放、取下、进桶；空桌面检查不产生成功记录。成功用仿真真值判断，接触计数增加会判失败。`expect: {planned: false}` 只接受规划器明确返回拒绝，不把异常当作预期通过。

已发现的待修项：原 `vertical` 的 unstack 和 bin_drop 会增加 block_contacts，涉及下面的支撑块；即便执行 ok、落点正确，bench 现在也输出 ok=false，并带 contact_records。零停短和 1.5° 停短均复现过。自动测试明确验证这两个失败被识别，不代表这两种动作已通过安全验收。叠放两层/三层和 bin_set 在零停短条件下为正常基线。未修改规划余量或把接触从统计中抹掉。

## 10. 统一检查

安装离线依赖：`pip install -r dev/requirements-offline.txt`，随后执行 `python -m playwright install chromium`。在项目根目录运行：

```powershell
.venv\Scripts\python.exe -X utf8 dev/tools/check_offline.py --profile all --android-serial emulator-5580 --adb "D:\SDK\platform-tools\adb.exe" --out data/checks/my-run
```

`--profile python` 检查日志 schema、全部内置脚本和模板 JSON，再运行两组完整 Python 测试（含浏览器、交互和场景）。`--profile android` 构建应用与测试 APK、运行 JVM 单测，再运行指定模拟器的 3 项 instrumentation 测试。`all` 合并两者。输出目录必须是新目录。完整档缺少模拟器会明确失败，不静默跳过；只接受 `emulator-*`，并检查 `ro.kernel.qemu=1`，不操作 adb 列表中的真机。

每个检查有独立标题、退出码、日志和耗时；最终 `report.json` 包含各阶段、运行环境和 `known_findings`。已知 vertical 接触问题会原样列出；测试通过的含义是“正常场景和失败识别符合断言”，不是所有机器人动作都零接触。

[`.github/workflows/offline-checks.yml`](../../.github/workflows/offline-checks.yml) 使用同一入口，分别运行 Python/浏览器与 Android 模拟器任务，并保存证据。Android 模拟器配置参考 [Android Emulator Runner 官方说明](https://github.com/ReactiveCircus/android-emulator-runner)。工作流已随 [PR #9](https://github.com/anweat/vision-robot-arm-sorting/pull/9) 推送，远程结果以 GitHub Actions/PR Checks 为准；本机结果不代替远程结果。

## 11. 落点测量记录模板（HT02/D2）

空白模板：[`placement-template.json`](../../records/hardware-tests/placement-template.json)；填写示例：[`placement-example-simulation.json`](../../records/hardware-tests/placement-example-simulation.json)。示例全部是构造数字，明确标为 simulation，不是实机记录。复制模板时用日期命名，不覆盖模板。

每块记录：日期、设备、版本 SHA、会话、地图/桶、速度；目标/实测坐标（基座系、米）、倾斜角（度）、是否碰邻块、测量方法、照片/日志证据。未知字段保持 null，不能填 0 代替未知。`verified` 由人工核对任务要求和独立证据后填 true/false，不能仅根据执行成功填写。

按 [44 R07](44-实机测试与调参清单.md) 的两种方法记录：对着地图码用直尺/卡尺量块心，或者放好后重扫、用 `located.json` 与目标位置比较；必须写清使用的坐标系与方法，叠放偏差以尺量为准。桶内不可见、倾斜看不清或邻块碰动无法判断时保持未知，并补照片或说明。平面偏差为目标与实测坐标的欧氏距离；示例为 5 mm。

填写后的 JSON 数组可以直接传给 `dev/tools/acceptance_stats.py --placements <文件>`。round 是统计输出中的 1 起轮号，block 使用报告中块名。空白模板不能作为完成的测量输入。
